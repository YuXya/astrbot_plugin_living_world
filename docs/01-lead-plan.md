# Living World 主程总计划 · 0.2.5

目标是一个沿用 AstrBot 人格、拥有连续日程、记忆、真实见闻与适度聊天的轻量角色 Agent。生活和记忆独立提供；B 站能力依赖 Bilibili AI Bot。支持 AstrBot `>=4.27.5,<5` 的 OneBot QQ 群聊与私聊。

代码交付与真实验收分开：本轮重构已有实现和自动化验证，全部保留功能的真实联调仍为后续验收终点。见[验收记录](03-delivery-and-validation.md)。

## 确定行为

- 每天默认 06:00 自动生成一次正式活动大纲，默认 10 个活动，保留起止时间、内容、地点和睡眠状态。生成时间与活动数可配置，修改默认次日生效；大纲不安排三类行动。
- 默认提前 10 分钟细化活动。AI 根据人格、活动、状态、相关记忆、当天其他安排、可见的近期实际行动、当前想法及模块和发送限制，自然判断是否安排新闻、搜索、主动聊天。每类给出理由、意图和时间，允许全部不安排；每个活动每类最多一次，可多类共存，按新闻、搜索、聊天执行。
- 独立“内在状态”页面管理寂寞值与精力：0—100，默认每在线小时增加 10，离线不补涨、每天不重置。日程主动聊天每轮默认减寂寞值 10，日程新闻和搜索每次分别默认减精力 10；数值、增长及消耗均可编辑。实际开始扣，失败不退，不足也允许执行并归零。其他手动来源、试跑、被动回复、插话、天气和独立日报不扣。
- 数值及机制完全由程序管理，模型只在细化时收到阶段文案，不看到数值、名称、阈值或增长消耗规则，不返回精力增减。默认阶段为 0—40、41—80、81—100，可增加、删除并编辑含义，始终覆盖全范围。“必须聊天”只是强烈倾向描述。取消三类行动每日活动上限及预留，保留各对象发送上限、冷却、免打扰与防重。
- 主动聊天找到符合限制的对象并开始生成消息时才计一轮，一轮可有多个不同对象；各对象共用原有发送、冷却和免打扰限制。消息和具体搜索选题到执行时生成，不提前编造结果。
- 未开始活动可手动细化、重新细化并填写仅用于本次的要求，正式与试跑共用请求组装；合格后事务替换旧结果。大纲修改后旧细化归档作废；自动失败后，在活动开始前至少隔 60 秒再试一次，仍失败则保留大纲，不新增行动。阶段或数值变化不会自动重新细化，下一次细化读取新文案。
- 管理员可点击「重新生成日程」，用最新已保存参数和当前模板重做今天整份大纲，不受自动生成时间限制。合格后事务替换并保留历史版本；失败、取消或跨日保留旧计划。新版本未来活动细化后照常执行，内在数值、实际行动记录、发送次数和冷却不重置，过期行动不补做。
- 生成大纲校验活动数和时间，细化另校验结构、活动范围内时间及新闻→搜索→聊天顺序，无固定次数和额度校验。完整请求、模型原始 JSON、生成参数、细化版本与实际执行结果分别保留。
- 本次升级保留已保存精力并初始化寂寞值 0，不追扣历史行动；归档未开始活动的旧细化和决定，保留大纲与场合，清空细化并重置尝试。已经开始的活动保留决定及结果，不再应用旧精力增减。旧日程模板备份后启用新默认，旧备份导入也先转换；不重放已执行或退役行动，记忆、发送记录及扣减凭据继续保留。
- 独立随机探索、临时主动联系取消；正常回复和群聊插话独立控制。
- 普通群聊默认在本轮 user 最后附加独立回复要求，可在调试页移动到 system 或其他位置，始终独立于生活资料块。默认只回应一个重点、通常一句，不复述背景或展开动作描写；文案在「05 聊天与对象 → 回复与插话」可改、可恢复默认，留空不附加。下一轮采用新设置，工具后沿用本轮快照，不写入聊天历史，私聊及后台任务不注入。
- 白名单按真实聊天目标匹配，按权重随机抽取配置数量的不同对象。人格、历史和记忆使用真实会话场合，继续统一频率、免打扰和防重控制。
- 支持首次联系，不要求已有历史。私聊沿用当前宿主对话；群聊独立观察近期 24 条、12,000 字符，生成时替换重复历史，保存前恢复。角色静态资料与本轮动态上下文分开，继续使用 AstrBot 模型、工具和回复流程。
- 调试按整轮展示四项：上下文来源与精确注入文本、实际 API 请求正文、实际 API 返回正文、回复阅读版。仅观察到普通消息不创建调试轮次，进入模型处理或实际发送时才记录；已确认的旧纯观察记录自动清理，不占聊天保留名额。工具后请求与 HTTP 重试逐次配对，流式保留 SSE 原文。真实失败与未捕获原文的调用仍保留，旧快照不冒充原文，第三方内部调用不属于捕获范围。
- 生活动态资料用中文段落，内部会话和存储字段不送给模型；稳定人格与动态资料分离，来源与组装同次生成。「角色、模型与模块」位于导航 02。
- 会话默认人格按宿主完整规则解析，检查与执行共用结果；配置允许和最近实际注入分别展示。聊天提供当前时间、当前活动及经过场合过滤的当天日程摘要，缺少日程或模块关闭明确标记。
- 天气固定和风，B 站固定 Bilibili AI Bot；六个默认新闻源可编辑、启停和恢复，搜索自动使用宿主配置。
- 黑鸦 Heya 12:00、橘鸦 Juya 23:00 两路 AI 日报独立定时，不占日程名额，不触发额外聊天，重启不集中补读。无法核对作者和日期时跳过。
- 来源保留事实、感想、选择理由、出处和阅读依据。获取失败不伪造经历，旧记忆和搜索不能记为新观看。
- 自动生活资料不附带来源链接及阅读依据字段，保留必要事实边界；角色经历按角色时区只注入今天的日常及派生记忆，统一显示时分并去除同事件重复副本。知识、人物认知和有效约定按原规则召回，来源原件、旧经历和历史调试继续保留。
- 管理员首页优先展示角色状态、当前活动、时间线、下次联系和最新见闻。独立提供白名单、调试记录、模型试跑和任务模板入口。
- 管理页面分为 8 个一级菜单与顶部全部可见的二级面板。「02 上下文与提示词」提供上下文排序、提示词模板、模型试跑、调用记录；角色、日程、聊天、来源、记忆和系统各自分工，完整入口见[管理页面指南](05-admin-navigation.md)。桌面上下文行高 32px，支持带占位和动画的拖动、角色切换及上下按钮；每块提供静态来源说明和准确管理跳转，元数据不进入模型。所有面板与对象草稿保存在页面内存，保存只提交本面板字段，旧链接保持兼容。触发、组装、场合和在途快照规则不变。
- 日记与笔记生成后分别保存完整正文和模型简报，日常上下文只使用简报。相关记忆总条数、其中日记／笔记条数及简报最长字符可在「记忆与人物」设置，默认 10／2／200；旧全文停止召回、可显式生成简报，生成失败保留存档，不批量补调用模型。

## 实施分工

一个主会话统筹，最多三个子智能体并行，按能力和文件范围分工。

1. 主程统一配置、持久化、后台调用与调试接口；日程、外部来源和页面分别建设。
2. 打通内在状态阶段文案、细化决定与执行扣减、阅读结果参与社交、真实会话记忆与白名单、独立日报及天气状态刷新。
3. 主程审查集成，完成自动化和页面回归、兼容核对、文档与测试包，再按真实连接条件组织整体验收。

## 验收效果

- 默认正式大纲恰好 10 个活动，不含行动决定；细化允许少做，可同时安排多类，无每日活动次数上限。不合格 JSON 被拒绝，旧细化保留。只有细化收到阶段文案，其他请求不自动加入内在数值或机制。
- “数学课无聊找群聊天”从细化决定到实际发送形成闭环；仅发出消息时不假定对方已回应。一轮多目标只计一轮，但各对象独立遵守发送限制。
- 局部修改只影响未开始活动，执行记录保持；关闭模块、失败和重启不重复触发已处理或过期行动。
- 昨日约定与更新后的记忆能影响所属场合的未来安排，私人信息不通过全局日程、日记或分享泄露。
- 白名单按权重随机选不同目标，实际消息仍受对象每日发送上限、频率和免打扰约束；已安排、已开始、成功、失败和跳过数量可查，重生成、重启和跨日不混淆计数或重复扣值。
- 在线增长、关停、手动修改、行动扣减、阶段拆分与合并均可核对；数值当前预览刷新不覆盖未保存设置，异常退出最多丢失最后一个保存周期的增长。
- 新闻、搜索、天气、视频和日报的真实依据可追溯；日报不消耗内在状态，旧视频记忆不冒充新观看。
- 调试能核对 SDK 实际发送的 HTTP 请求及原始返回，聊天默认保留 10 轮完整过程、后台每类 10 次；试跑无工具、QQ 或正式数据副作用，公共模板不自动固化私人上下文。
- 首次主动私聊成功后，接下来的回复可接续；新建或切换对话不拼入旧全文，群聊不重复注入或损坏原始历史；并发、失败、取消、调试关闭及卸载均有回归验证。
- 首页状态、时间线和白名单入口清楚；所有操作注明影响范围及是否调用模型、来源或发送消息。

## 共用边界

认识同一个人，谈话分场合。稳定人物认知可贯通，具体谈话、约定及衍生记录保留场合；角色自己的生活经历与公开见闻可共用。首页和调试属于经过 AstrBot 认证的管理员视图，不能据此放宽聊天的资料过滤。

所有业务能力分别可关闭并保留数据。升级与备份恢复保留执行防重记录；调试记录清理不影响正式日程或记忆。试跑输入和公共模板分离，外部插件返回与其内部调用区分。

不安排完整世界模拟、其他居民、人格自我改写、饥饿、梦境、多 AI 持续交流或复杂技能成长。实现不预设消息总线、固定工位或逐项 ADR；公开发布和插件市场上架另行安排。任务卡见[索引](README.md)。
