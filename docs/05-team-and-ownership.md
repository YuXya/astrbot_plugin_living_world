# 团队、所有权与交接

## English Summary

The project is organized as nine accountable work packages (P0–P8). Each module has one owner, cross-module behavior is changed through reviewed contracts, and a four-slot execution model is used for parallel work. This document defines ownership, RACI, handoffs, and merge gates.

## 编制与职责

| 工位 | 主责 | 独占所有权 | 主要交接对象 |
|---|---|---|---|
| P0 主程 / 架构 / 集成 | 产品边界、契约语义、ADR、集成、版本与最终发布 | 根文件、`main.py` 装配、`contracts` 语义 | 全员 |
| P1 内核工程师 | 总线、时钟、生命周期、任务监管、持久化基础设施与恢复 | `kernel` | P0、P2、P8 |
| P2 世界模拟工程师 | 身份与叙事世界、日程规划、当前活动及叙事位置状态 | `world`、`planner`、`state` | P1、P3、P4 |
| P3 记忆上下文工程师 | AI 生活账本、AstrBot 原生会话读取、临时上下文 | `memory`、`conversation` | P0、P2、P6 |
| P4 环境工程师 | 和风天气、现实天气查询位置、缓存、标准化环境观察 | `environment` | P2、P8 |
| P5 探索集成工程师 | 新闻、AstrBot 搜索与 B 站公开能力适配 | `exploration` | P3、P6、P8 |
| P6 社交主动工程师 | 对象资格与排序、候选生成、逐目标个性化、OneBot 投递 | `audience`、`proactive` | P3、P5、P8 |
| P7 管理前端工程师 | 配置、命令、Plugin Page、诊断、导入导出和审计投影 | `admin` 与页面资源 | P0、各模块负责人 |
| P8 QA / 安全 / 发布 | 自动化测试、架构守卫、隐私、许可证、CI 与发布验收 | 测试策略、发布清单与质量报告 | 全员 |

逻辑模块卡见 [`modules/`](modules/README.md)，每个工位的可执行任务卡见 [`work-packages/`](work-packages/README.md)。模块所有权是写入权和评审责任，不是信息孤岛。

## 修改边界

- 每位负责人只直接修改自己拥有的模块、对应测试、模块卡和任务卡。
- `contracts`、根文件、主入口和公共装配由 P0 串行合并；其他工位通过提案或独立提交请求变更。
- 业务模块不得导入其他业务模块实现、访问其他模块数据表或绕过消息总线调用内部对象。
- P7 的页面通过管理命令和只读投影工作，不能直接编辑模块存储。
- P8 可以新增测试、检查和发布配置；修复业务实现仍由对应所有者完成。
- 涉及两个模块的提交必须拆成“契约/ADR”“各自实现”“集成测试”三个可审查部分，避免一个提交取得多模块写入权。

## RACI

`A` 为最终负责，`R` 为执行，`C` 为必须会签，`I` 为知会。

| 决策或交付 | P0 | P1 | P2 | P3 | P4 | P5 | P6 | P7 | P8 |
|---|---|---|---|---|---|---|---|---|---|
| 产品范围、版本目标 | A/R | I | C | C | I | I | C | C | C |
| 消息信封与兼容策略 | A/R | C | C | C | C | C | C | C | C |
| 总线、时钟、恢复语义 | A | R | C | C | I | I | C | I | C |
| 世界、日程、状态规则 | C | C | A/R | C | C | I | C | C | C |
| 记忆与会话隐私边界 | A | I | C | R | I | I | C | I | C |
| 天气与现实查询位置适配 | I | C | C | I | A/R | I | C | I | C |
| 新闻、搜索与 B 站适配 | I | C | I | I | I | A/R | C | I | C |
| 主动选择与 OneBot 投递 | C | C | I | C | I | C | A/R | C | C |
| 管理页面与运维入口 | C | I | C | C | C | C | C | A/R | C |
| 发布放行 | A | C | C | C | C | C | C | C | R |

任何一项只有一个 `A`。P0 可以否决破坏产品边界、许可证、隐私或兼容承诺的变更；P8 可以因可复现的质量、安全或发布门禁失败阻止发版。

## 契约变更流程

1. 提议者先描述动机、生产者、消费者、失败语义和兼容影响。
2. P0 更新或批准对应 ADR 与 `03-event-contracts.md`；P8 先补契约兼容测试。
3. 所有受影响模块负责人会签，确认旧消费者的降级路径。
4. P0 冻结新版本后，各所有者才并行实现。
5. 集成测试证明旧版本可接受、拒绝或迁移；不得静默误读。

仅重命名字段也属于契约变更。紧急修复若改变跨模块语义，仍需最小 ADR 和回归测试，不得以热修复绕过流程。

## 四并发工位的执行波次

| 波次 | 并发工位 | 目标 | 退出条件 |
|---|---|---|---|
| 0 | P0、P1、P8 | 冻结契约、建立内核与测试框架 | 模拟总线、虚拟时钟、契约测试可供其他人使用 |
| 1 | P2、P3、P4、P5 | 并行完成世界生活、记忆上下文、天气与探索 | 各模块只依赖模拟事件即可通过验收 |
| 2 | P6、P7、P0、P8 | 主动链路、管理页和全局集成 | OneBot 沙箱链路与管理黑盒测试通过 |
| 3 | P0、P1、P8、轮值负责人 | 稳定化、迁移、故障演练与发布 | 候选版本满足 `07-testing-integration-release.md` |

波次表示容量安排，不表示可以跳过依赖门禁。未冻结的契约不得靠口头约定并行开发。

## 标准交接包

每次模块交接必须包含：

- 对应模块卡与已批准 ADR；
- 消费和发布的事件清单、版本及示例夹具；
- 正常路径、超时、重复、乱序、不可用和重启恢复的测试证据；
- 数据所有权、迁移和删除说明；
- 可观测指标、错误码与降级行为；
- 已知限制及下一位负责人无需猜测的待办。

接收方只基于公开契约和测试夹具联调。若必须读取对方内部实现才能完成工作，视为架构缺陷，退回 P0 处理。

## 合并与完成定义

进入评审前，负责人需证明：范围与任务卡一致、模块单测通过、契约测试通过、没有越权导入或跨库写入、文档与行为一致。合并至少需要模块所有者和 P0 审核；涉及隐私、外部凭据、主动发送、迁移或许可证时，P8 必须会签。

“完成”同时要求实现、测试、错误处理、诊断、文档和交接包齐全。只能在个人环境运行、依赖真实外部服务才能验证或无法通过模拟事件复现的功能不算完成。
