# 0.1.0 安装与测试说明

本版本用于首轮安装测试。代码实现和自动化验证已开展，真实模型、OneBot QQ 收发、B 站账号及完整宿主页面操作仍需按下列步骤联调。返回[文档索引](README.md)。

## 安装环境

- Python 3.12，AstrBot `>=4.27.5,<5`；此前完整自动化验证基线为 `4.28.0b1`。
- 已配置的 AstrBot 对话模型、一个可绑定的人格，以及用于实测的 OneBot QQ / `aiocqhttp` 平台。
- 安装本插件 `requirements.txt` 中的依赖；使用 AstrBot 自身运行的环境，不要装到另一个 Python 环境。
- B 站是可选依赖：安装并启用 `astrbot_plugin_bilibili_ai_bot`，提供 `search_bilibili`、`watch_video` 和公开记忆 API v3。登录、视频解析及模型条件由该插件自行配置。

在插件管理导入 ZIP，或将插件放到 AstrBot 的 `data/plugins/astrbot_plugin_living_world`。检查该目录下直接存在 `main.py`、`metadata.yaml`、`requirements.txt`、`living_world/`、`pages/`，再加载插件。

本插件不依赖 private_companion 或 Angel Memory。不要把本地开发虚拟环境、测试缓存、数据库和个人配置打进插件 ZIP。

## 首次接入

1. 打开 AstrBot 中本插件卡片的 Plugin Pages 管理入口。`/living_world` 仅显示运行状态，业务设置在页面完成。
2. 选择一个 AstrBot 人格，补充角色资料、世界设定、时区和轻量状态。核心人格仍由 AstrBot 管理。
3. 在测试群或测试私聊使用 `/sid`，将完整 UMO 加入白名单。典型格式为 `平台实例ID:GroupMessage:会话ID` 或 `平台实例ID:FriendMessage:会话ID`；启用 `unique_session` 的群会话可能是 `用户ID_群ID`，不要自行改写 `/sid` 返回值。
4. 在 AstrBot 中让对应会话使用同一人格。页面诊断提示人格不一致时，先处理绑定问题；插件不会接管使用其他人格的会话。
5. 打开宿主群历史，以便主动消息能参考群内话题。若要测试本插件插话，关闭宿主概率回复；宿主概率回复仍开启时，本插件主动暂停插话。
6. 模型留空会沿用 AstrBot 当前默认。需要隔离调用成本或使用不同模型时，在页面设置插件默认及业务覆盖。
7. 保存前检查模块开关。初次安装未绑定人格时不自动行动；保存有效绑定后，已开启模块即可运行。主动联系、插话和外部来源默认关闭，按实测需要逐项开启。

管理页面是唯一配置入口，配置与运行数据保存在 AstrBot 插件数据目录的 `astrbot_plugin_living_world/living_world.sqlite3`。本插件没有 `_conf_schema.json`；不要另建一份插件配置与页面并用。

## 外部来源配置

| 能力 | 配置内容 | 实测时应确认 |
|---|---|---|
| 新闻 | `news.feeds` 填 RSS/Atom URL 数组，`news.limit` 控制返回条目数 | 能读到标题、摘要与原文出处，一个失效来源不妨碍其他来源 |
| 搜索 | `search.tool_name` 指向已启用的只读搜索工具，`search.query_argument` 与工具关键词参数一致 | 实际执行该搜索工具，不配置发送、发布或其他写操作工具 |
| 天气 | `weather.url` 为返回 JSON 的 HTTP(S) 地址，`weather.location` 为位置；URL 可包含 `{location}` | 接口返回真实天气数据，凭证错误或空结果不会写成查询成功 |
| B 站搜索 | `bilibili.plugin_name` 默认 `astrbot_plugin_bilibili_ai_bot` | 调用 `search_bilibili`，记录视频搜索结果，不自动声称已观看 |
| B 站观看 | 模型或管理页面选择 `bilibili_watch`，参数为完整 BV 号 | `watch_video` 明确确认完成；旧缓存或曾经看过的内容标为读取记忆 |
| B 站记忆 | 模型或管理页面选择 `bilibili_recent` | 只通过 API v3 读取公开视频记忆，不读取私信或触发互动 |

当前不内置新闻供应商、搜索服务或天气账号。B 站不运行依赖插件的完整自主浏览流程，不调用点赞、投币、收藏、关注、评论、私信等工具。来源失败、依赖停用或空配置会返回原因，其他能力可继续运行。

## 联调顺序

1. **安装与基础接入**：确认加载成功、管理页面可打开、绑定生效；不绑定或人格不匹配时，无对应自动行为。
2. **生活与记忆**：生成日程，确认小插曲标为角色虚构经历；在测试会话留下约定，检查更新后的记忆能调整未来安排，已执行活动保持不变。
3. **主动社交**：只用明确配置的测试白名单，测试“数学课无聊，找群聊天”、临时主动联系、数量与权重配置、免打扰及频率限制；发送成功不应被记录为已经得到回应。
4. **场合隔离**：在测试私聊留下具体约定，再到测试群查看召回、主动消息和日记；稳定人物认知可共用，私聊正文和约定不应出现。
5. **外部见闻**：分别获取新闻、搜索、天气与 B 站结果；验证来源可追溯，查询失败不会产生成功记录，搜索与观看结果可区分。
6. **启停与恢复**：执行中关闭模块、移除白名单或更换人格，确认对应行为停止；重载、重启后保留记录，过期消息不集中补发，不重复执行已有行动。
7. **页面与备份**：编辑角色、日程和记忆，浏览日记与调用记录；导出后在测试数据目录恢复并复查设置与记录。

每一步记录宿主版本、测试配置范围、实际结果和失败现象；不记录密钥或完整私聊。单个用例通过不能替代整套真实环境验收。

## 自动化验证与备份

在隔离的 Python 3.12 开发环境安装测试工具和相同宿主基线后，可在插件根目录运行：

```text
python -m pytest -q
python -m ruff check main.py living_world tests
```

自动化覆盖存储、记忆场合过滤、日程与实际动作分离、概率抽选、来源替身、启停恢复及宿主适配等行为，不向真实 QQ 会话发送消息。实际覆盖及待办见[交付与验收记录](03-delivery-and-validation.md)。

导入备份会恢复设置，合并当前不存在的记录，不覆盖已有 ID 或执行防重记录，并关闭全部业务模块；检查人格、会话、来源和频率后再开启。导出文件可能含私人内容和来源 URL 凭证，仅本地保存，不提交仓库。
