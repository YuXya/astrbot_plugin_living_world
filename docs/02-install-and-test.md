# 0.2.5 安装与测试说明

> 2026-09-11 最新规则：当前仅使用已保存的现行格式：布局 v4、用量 v2、统一记忆 v2；新安装缺失项使用当前默认值，不执行旧配置、旧日程、内在状态或旧记忆迁移。备份格式为 v2，旧备份直接拒绝，不转换或重放旧任务。
本插件支持 **Python 3.12、AstrBot `>=4.27.5,<5`**，使用 OneBot QQ / `aiocqhttp`。当前本地自动化环境为 Python 3.12.14、AstrBot 4.28.0，版本以实际导入的宿主源码为准；4.27.5 已核对官方发布标签源码，真实环境联调另记。

菜单、来源索引和草稿使用方法见[管理页面指南](05-admin-navigation.md)。本次按桌面体验验收。

## 安装与升级

1. 在 AstrBot 插件管理导入 `astrbot_plugin_living_world-0.2.5.zip`；或将目录放到 `data/plugins/astrbot_plugin_living_world`，根目录直接包含 `main.py`、`metadata.yaml`、`requirements.txt`、`living_world/`、`pages/`。
2. 使用 **AstrBot 实际运行的 Python 环境**安装 `requirements.txt` 中尚未安装的依赖，再加载或重载插件。
3. 在插件卡片打开 **Plugin Pages**。`/living_world` 只显示插件运行状态；配置、白名单和调试均在页面操作。
4. 升级前可在「08 系统与数据 → 备份恢复」下载备份。**本次新增并默认开启内在状态模块**：寂寞值从 0 开始，精力沿用当前保存值，历史行动不追扣。归档所有未开始活动的旧细化和行动决定，保留大纲及场合，清空细化并重置尝试，等待按新规则细化；已开始活动保留决定和记录，旧精力增减不再应用。记忆、白名单、实际发送、冷却、防重和扣减记录保留，无 SQLite 表结构迁移。
5. 生成、细化和调整日程的旧自定义模板会备份，当前流程启用新默认模板。「02 上下文与提示词 → 提示词模板」可按任务和版本查看升级前指令；转换只执行一次，不覆盖之后的新修改。导入旧备份也先转换，不能重新激活已退役活动。

生活和记忆无需安装 private_companion 或 Angel Memory。B 站能力依赖已启用的 `astrbot_plugin_bilibili_ai_bot`，要求 `search_bilibili`、`watch_video`、公开记忆 API v3；其账号、视频解析和模型由该插件自行配置。

配置与数据统一保存在 AstrBot 插件数据目录的 `astrbot_plugin_living_world/living_world.sqlite3`，不在代码目录。Plugin Pages 是唯一配置入口，没有 `_conf_schema.json`。

**接入和日程验证：**升级并重载后，在白名单点击「检查会话与历史」。沿用默认人格的会话应显示实际人格和来源；无需重建。确认「日程生活」「被动回复」「调试记录」已开启，发送“现在日程是什么？”，查看最近实际注入及对应调试记录。在②API 原始请求里搜索“当前时间”“当前活动”“今日日程”，并核对具体内容。缺少日程或模块关闭会提供中文说明。

**三份回复要求：**打开「05 聊天与对象 → 回复与插话」，分别编辑「本轮群聊回复要求」「本轮私聊回复要求」「本轮主动聊天要求」，再点击「保存回复与插话设置」。各自可恢复默认、留空关闭，最长 8000 字符；升级保留群聊文案，私聊及主动聊天首次复制原群聊内容（包括空值），之后各自保存。默认分别用于 chat.group、chat.private、social.message；插话正文沿用主动聊天要求，插话判断默认不勾选，其他任务也可自行勾选这些要求。位置遵循全局排序，始终是生活资料块外的独立指令；下一轮生效、工具后沿用本轮快照，不进入宿主历史，不截断输出或额外调用 AI 复核。

**名字与三条日程：**交谈对象资料只显示名字及类型、接收范围；优先白名单手填称呼，否则只读对应 QQ 连接的昵称／群名，成功缓存一小时、失败一分钟、读取超时两秒，失败显示“未设置名字”。号码仍在管理和实际发送中使用。普通群聊、私聊及主动聊天默认勾选简版日程：当前活动存在时取上一条、当前条、下一条，空档取最近两条过去活动和下一条未来活动。按角色时区当天及当前场合筛选，排除取消／退役活动，最多三条且不跨日补齐；保留每条完整正文、时间、真实状态、地点和睡眠，不另调用模型摘要。可在上下文排序中改选完整日程或全部取消。

## 统一记忆与上下文用量

记忆统一为「记忆与画像」和「近期记忆」两个上下文入口：自身稳定画像默认 5 条、每人稳定画像 5 条、相关记忆 10 条、近期记忆 5 条，群聊最多 3 人，天气独立 1 条。用量位于「02 上下文与提示词 → 上下文用量」，0 停止对应注入，默认合计上限 36 条。近期记忆优先去重，按实际经历或获知时间跨日选择；未勾选项不影响其他项。日记与笔记保存正文后进入统一后台提炼，取消独立简报流程。详见[统一记忆指南](07-memory-system.md)。

打开 **07 记忆与日记 → 记忆与画像** 查看自身与 QQ 人物档案，搜索、编辑、标记重要及查看变更。**提炼与遗忘** 配置聊天批次、闲置处理和三档遗忘参数，并显示迁移与待提炼进度。遗忘默认关闭，开启后只累计在线启用时间；达到条件彻底删除记忆及版本，来源记录保留。

升级先归档旧配置和数据，自动分批整理旧记忆、经历、见闻、日记和笔记，会调用记忆模型；可暂停、继续，失败可重试，无法解析人格时暂停相关整理。记忆模型留空沿用宿主。日记和笔记从新记忆取材，保存正文后交给同一后台队列，不再单独生成简报。

## 首次配置和白名单位置

1. 打开「角色、模型与模块」，绑定一个 AstrBot 人格，填写角色与世界资料、时区和初始状态。模型留空沿用宿主，也可设置默认模型及业务覆盖。
2. 进入左侧 **「聊天对象与白名单」**，点击「添加聊天对象」，填写 **QQ 连接、群聊／私聊、号码、启用、权重**，点击「保存聊天对象与限制」。首页「今日生活」顶部和「日程与行动」参数卡也能直达。
3. 表单自动生成完整会话 ID。原有 UMO 配置继续兼容；如需排查，目标会话中的 `/sid` 可查看宿主实际 UMO。不要把群号当成 QQ 连接 ID。
4. 让所选目标会话在 AstrBot 中使用同一人格。白名单按实际目标识别，记忆与人格按真实会话处理；开启 `unique_session` 时保留宿主的用户与群会话边界。
5. 未聊过的对象也可接入，点击「检查会话与历史」查看人格与历史状态；不创建空会话。群聊无需开启宿主群历史，从新收到的消息积累观察；已有宿主群历史可初始化窗口。使用本插件群聊插话时关闭宿主概率回复，否则插件暂停插话避免双重响应。
6. 保存冷却、每个对象的每日发送上限和免打扰。每轮固定抽选一个合格目标。权重影响随机抽中概率，不是内容相关性排序；一次抽选不重复选中同一目标。这项发送上限继续保留，与已取消的“每日主动聊天轮次上限”不同。
7. 主动社交、插话和外部能力默认关闭，先配置明确的测试目标再启用。未绑定有效人格时插件不自动行动。

页面是 AstrBot 管理员视图，可以查看所有场合；聊天中的召回仍按所属场合过滤。不要将管理页面的完整内容直接分享给普通聊天对象。

## 内在状态：寂寞值与精力

进入 **「03 角色与状态 → 内在状态」** 面板，上方同时显示两项当前值、命中阶段和下次活动细化会收到的实际文案。下方通过下拉框选择 **「寂寞值」或「精力」**，一次查看一项。两项均由程序管理，AI 看不到数值、参数名称、阶段范围和增减规则，也无法控制增减。

| 设置 | 寂寞值 | 精力 |
|---|---|---|
| 初始值 | 0 | 沿用已保存精力；新安装默认 70 |
| 默认增长 | 每在线小时 +10 | 每在线小时 +10 |
| 默认消耗 | 每轮日程主动聊天 -10 | 每次日程新闻 -10、每次日程搜索 -10，分别设置 |
| 范围 | 0—100 | 0—100 |

按在线时长连续计算，内部保留小数，展示和阶段匹配向下取整。例如在线半小时从 0 增长到 5。每天不重置，离线不补涨；到 100 后不继续积攒。插件每 60 秒保存，并在扣值、手动修改和正常关闭时保存；异常退出最多丢失最后一个保存周期的增长。

当前值使用独立的 **「应用当前值」** 操作，立即生效；**「保存设置」** 只保存增长、消耗和阶段，不会把表单中的旧值覆盖到正在增长的当前值。增长量和各项消耗允许设为 0。关闭内在状态模块后停止增长、扣减和文案注入，但保留数据并允许人工修改；重新开启从当前值继续。恢复备份时，内在状态也随所有模块一起关闭。

默认阶段与文案如下，均可编辑：

| 范围 | 寂寞值文案 | 精力文案 |
|---|---|---|
| 0—40 | 不是很想聊天。 | 暂时不太想阅读新闻或主动搜索。 |
| 41—80 | 想偷偷看一眼 QQ 聊天。 | 想了解新鲜事，或查查感兴趣的问题。 |
| 81—100 | 必须聊天。 | 很想阅读新闻或主动搜索，了解些新东西。 |

每行 **“＋”** 把该阶段约分成两半，新段沿用原文案；只有一个整数值的阶段不可拆分。删除阶段时合并到相邻低一档，删除最低档时并入下一档，仅剩一档时不能删除。调整分界会自动修改相邻范围，保证覆盖 0—100，没有空档和重叠。刷新预览不丢失未保存的设置。

**“必须聊天”只是强烈提示，AI 仍结合活动与限制决定是否安排。** 数值到达新阶段不会立即执行行动，也不会自动重新细化已有活动；下一次细化读取新文案，需要立即改变决定时手动重新细化。

### 什么时候扣值

- 只有日程安排的真实行动扣值。新闻、搜索通过能力检查并开始本次模型或来源调用前扣精力；聊天找到合格目标并开始生成消息前扣寂寞值。
- 一轮聊天可联系多个不同对象，只扣一次。没有合格目标、能力关闭、过期或发送限制导致开始前跳过时不扣；已经开始后失败或结果不确定不退还。
- 数值不足仍允许执行，最低扣到 0，不把数值当作执行资格。
- 手动来源调用、调试试跑、被动回复、群聊插话、天气和独立 AI 日报不扣。每个对象的白名单、每日发送上限、冷却和免打扰继续生效。
- 扣减与行动开始凭据事务保存，重启、重新生成日程或恢复旧备份不会重复扣同一行动。

## 日程大纲、细化和行动

「04 日程与行动 → 生成与细化设置」保存大纲与细化参数，点击 **「保存日程设置」**不调用模型：

| 设置 | 默认值与生效方式 |
|---|---|
| 大纲生成参数 | 每天 **06:00** 自动生成一次，共 **10 个活动**。生成时间和活动数修改默认次日生效；保存后可手动重新生成今天的日程。 |
| 提前细化活动 | 默认提前 **10 分钟**，可设 0—120 分钟；细化决定具体内容和是否安排行动。提前量为 0 或小于后台检查周期时，至少按一轮周期（默认 60 秒）提前尝试，仍须在活动开始前采用。 |

大纲只包含活动起止时间、标题、内容、地点和睡眠状态，校验活动数与时间，不要求新闻、搜索或主动聊天恰好出现多少次。三类行动已取消每日活动上限和名额预留。每个活动每类最多一次，可以多类共存；没有具体需要时允许全部不安排。

### 细化时 AI 收到什么

程序组装 **公共细化模板 + 本次动态资料 + 可选本次要求**。资料包含当前时间与活动、人格与作息、心情和相关记忆、当天其余活动摘要、内在状态映射的“当前想法”，以及本场合可见的近期实际行动和当前模块、免打扰等限制。公共细化不会取得其他场合的私人谈话或发送正文。

例如当前想法是“想偷偷看一眼 QQ 聊天。想了解新鲜事，或查查感兴趣的问题。”，AI 再结合晚间散步决定是否安排聊天、新闻或搜索。程序不会附加“寂寞值 60”“精力 50”等数值说明。提示词要求只提出未来行动，不编造已读新闻、搜索结果、已发送消息或对方回复。

未开始活动可以点击 **「细化活动」**或 **「重新细化」**，填写“本次要求”，例如“这次专心散步，不安排主动聊天”。这些文字只用于本次，不保存到公共模板，也不能突破发送限制。正式调用与调试试跑共用请求组装逻辑，实际模板、动态资料和 API 收发可在四项调试中核对；试跑不扣值、不执行行动。

细化返回活动细节、角色虚构的小插曲和心情，并为新闻、搜索、主动聊天分别返回是否安排、理由、意图和时间，不再返回精力增减。程序校验结构、活动内时间和新闻 → 搜索 → 聊天的顺序；具体选题、搜索词和聊天正文到执行时才生成。合格后采用；重新细化会归档并替换旧结果。失败、取消、活动已改变或已经开始时，旧结果保持。

自动细化失败后，只在活动开始前、距上次尝试至少 **60 秒**时再试一次；重启不重置次数。仍失败则保留活动大纲，不新增三项行动，活动开始前可手动重试。页面展示失败原因、细化决定和折叠历史版本。

### 行动统计

- 页面显示已安排、已开始、成功、失败和跳过，主动聊天明确按“轮次”统计；实际消息条数另行记录。
- 已安排按当前采用版本的行动计划时间归属日期统计，包含已执行或已跳过的决定；已开始按实际执行日期跨版本统计。管理员统计包含私人场合行动，不向公共模型请求提供私人详情。
- 开始前跳过不算已开始；开始后失败或结果不确定保留真实开始记录，包含被替换旧日程的实际行动。
- 按角色时区的实际执行日期统计，重生成、重启、导入旧备份不会清零记录或重放行动。过期行动跳过，不集中补做。

### 调整或重新生成今天

**「编辑」或「批量调整未来活动」**只修改尚未开始的活动大纲，保持原活动数。时间、内容、地点等改变后，旧细化归档作废，之后自动或手动重新细化。保存不调用模型、不发送消息；具体私人约定的调整继续限于所属场合。

**「重新生成日程」**仅支持今天，有无旧日程均可使用，不受默认生成时间限制。先保存参数，再确认调用模型；使用本次操作开始时已保存的参数和模板重做今天整份大纲。合格后立即采用，当前时间线和聊天日程上下文切换新版本；失败、取消、跨日或模块关闭保留旧日程。

重生成等待正在执行的日程轮次结束，生成期间暂停日程推进并禁止活动编辑、细化和重复提交。新版本的未来活动细化后照常执行，**内在数值和实际行动记录不重置**，既有实际行动不撤销，白名单、发送次数、冷却和免打扰仍然生效。

「正式日程生成档案」保留当前版本的参数、完整输入快照、模型生成文本和采用结果；下方折叠历史保留旧活动及实际执行记录，可查看、下载和跳转关联 API 记录。细化另有历史版本。历史档案不随调试清理删除，恢复旧备份不能重新激活退役活动；其他日期的大纲生成仍使用调试试跑。

独立随机空闲阅读、搜索和临时主动联系不再运行，旧的日程外主动联系入口不发送消息。被动回复和群聊插话仍独立控制。

在「06 见闻与来源 → 来源设置」按类型和对象选择并保存配置，在「近期见闻」查看事实、感想和历史记录，「手动读取」提供实际读取操作。日记在「07 记忆与日记 → 日记与笔记」。

| 来源 | 默认与配置 | 操作说明 |
|---|---|---|
| 新闻 | BBC 中文、Google 新闻中文、Solidot、Hacker News、MIT Technology Review、Ars Technica | 选择新闻源后可改名称/地址、启停；「恢复默认」恢复六路配置，保留历史。AI 先从候选选一条，再读取并写感想。 |
| 搜索 | 沿用 AstrBot 的网页搜索开关和服务配置 | 先在宿主配置可用搜索服务。无需在插件里填写工具名、参数名或另一套密钥。 |

| B 站 | 固定 Bilibili AI Bot，显示依赖状态 | 提供搜索、完整 BV 号观看、公开视频记忆读取。缺少或停用依赖时，对应能力跳过。 |
| AI 日报 | 黑鸦 Heya UID `3706929260006322` 默认 12:00；橘鸦 Juya UID `285286947` 默认 23:00 | 可改时间与来源设置、逐路启停或恢复默认；每天各执行一次，不消耗内在状态，不额外聊天。 |

天气先解析地点，再读取和风实时天气。自动刷新成功后间隔 90 分钟，失败后退避 15 分钟；改变配置可重新尝试。**天气不会调用模型。**「测试天气连接」使用已保存配置，真实访问和风，但不写正式见闻、日程或记忆。

B 站日报通过只读视频信息确认作者和当天发布日期，不能确认时标明原因并跳过。搜索不代表观看；读取旧视频记忆会明确标记。插件不调用 B 站完整自主浏览、点赞、投币、收藏、关注、评论或私信流程。

「06 见闻与来源 → 手动读取」提供明确按钮：读取新闻并写感想、搜索并保存见闻、读取天气并保存、搜索 B 站视频、观看指定视频并保存、读取公开视频记忆。这些操作会真实调用来源、必要时调用模型并保存正式见闻，**不会主动发送 QQ**，也不会篡改计划行动的防重记录。

标题/订阅摘要、网页正文、搜索结果、视频分析与旧记忆分别标明阅读依据。获取失败不写成功见闻；模型整理失败仅保留已取得证据，感想留空，标记部分完成。

## 调试：AI 到底收到了什么

进入 **「02 上下文与提示词」**，顶部选择「上下文排序」（默认）、「上下文用量」、「提示词模板」、「模型试跑」或「调用记录」。调用记录按类别与轮次下拉选择，一次展开一轮，支持前后轮切换。每条记录仍固定四项：①上下文与信息来源、②API 原始请求、③API 原始返回、④回复阅读版。默认保留最近 10 轮完整聊天、后台每类 10 次完整调用，重试和子调用一起保留；可调整数量、按类别筛选与清理。

普通群友消息只参与群观察；未进入模型处理、也未实际发送的消息不创建聊天调试记录，不占最近 10 轮名额。更新并重载后自动清理可确认的旧纯观察记录，恢复旧备份时同样清理。模型准备或调用失败、取消、尚未捕获 HTTP 原文及实际发送记录继续保留，不以②③④为空作为删除条件。清理不影响群观察、宿主历史、记忆或发送防重数据。

第二、三项来自 DeepSeek/OpenAI 兼容 Chat Completions 与 Responses 的实际 HTTP 正文，提供独立复制下载。多次请求通过下拉切换，收发一一配对；流式返回保留 SSE 原文，阅读版另行合并。认证凭据隐藏，未知参数和返回字段保留。未适配或未取得原文明确标注，不使用 Provider 参数代替。

四项仍通过按钮选择。第一项的来源按单列显示，默认展开，可分别收起；第二、三项默认提供 JSON 缩进与正文换行，也可切换原文。格式化只影响页面阅读，复制和下载始终保留保存的原始正文。

格式化 JSON 中的对象和数组默认展开，左侧小箭头可分别收起，另有“全部展开”“全部收起”。折叠状态按记录、请求及收发方向分别保留，正文变化时重置；收起后的复制下载仍包含完整原文。

第一项提供同次组装的来源和实际注入文本；第四项提供回复、推理、工具、用量、结构化结果和发送状态。旧日志标为“旧版快照，非 API 原文”。SDK HTTP 重试分别记录，第三方插件内部请求不捕获。完整说明见[聊天上下文与调试指南](04-chat-context-and-debug.md)。

清理不删除正式日程、记忆、群观察或发送防重。正式日程另存生成输入快照、模型生成文本和采用结果，可跳转关联调用；调试清理后不能再恢复对应 HTTP 原文。

## 隔离试跑与模板

分别进入「模型试跑」和「提示词模板」面板。任务选择器和模板标题显示原名字及中文说明，例如 `memory.reflect（记忆提炼）`、`social.interject（群聊插话判断）`；内部任务标识不变。菜单、任务、页面切换和数据刷新保留尚未保存的试跑、模板、保留数量及布局草稿；关闭或重新加载浏览器仍需先保存。

1. 从某条模型记录建立测试请求，或选择任务和场合后点击「从当前配置建立测试请求」。这一步不调用模型。
2. 选择「组合模板与动态上下文」时，编辑 JSON 的 `template`、`dynamic_context`，有布局快照时也可编辑 `context_layout`、`base_system_prompt` 和 `context_blocks`；版本 4 快照另有 `context_selection` 保存本次勾选，试跑使用该请求快照组合，`prompt`／`system_prompt` 是预览，不读取新的全局排序。旧请求没有布局快照时保留原组合方式。
3. 选择「直接编辑完整 prompt」时，显式 `prompt` 和 `system_prompt` 就是本次输入。两种模式都可编辑 `contexts`、`provider_id`、`model`、`parameters`。文本以及 `image_urls`、`audio_urls` 可供模型测试；包含非空 `extra_user_content_parts` 或 `tool_calls_result` 的特殊记录会明确拒绝直接试跑，请把需要的文字资料整理进 `contexts`。
4. 点击「仅调用 AI 试跑」会真实调用模型，可能产生费用，保存测试调试结果；**不执行工具、不发送 QQ、不改正式日程、记忆或生活数据**。
5. 「提示词模板」单独保存公共任务指令，可恢复默认。试跑 JSON 不会自动保存到公共模板；不要把私人记忆、某次活动或整个请求粘进公共模板，动态内容由每次调用注入。

试跑适合检查日程 JSON 和提示词，不是 QQ 发送验收。需要真实行动验收时，使用正式日程中的未开始测试活动和已配置测试白名单。

## 调整上下文位置

在「上下文排序」通过「调整范围」选择任务；该选择仅切换本任务勾选项，排序全局共用。system 和本轮 user 各有一列，**从上到下就是实际注入顺序**。拖动资料行左侧手柄、点击上下按钮或用键盘聚焦按钮后按 Enter；角色下拉框可把资料移到另一组，再继续排序。原系统提示词、本轮原始消息／后台任务提示词为只读定位行，资料可排在其前后。

新安装默认角色补充资料与世界设定放 system，动态资料及回复要求放 user；升级保留已保存全局位置。记忆与画像、近期记忆分别移动，取代旧分类资料行；近期记忆接替旧经历位置，记忆与画像接替最早旧记忆位置。天气、日程和任务材料保持独立，提炼所需原文仅使用明确任务输入。

所有任务显示相同完整列表，包括未勾选行；除只读人格和原始消息定位行外均可勾选、拖动、上下移动和切换角色。在任何任务下排序都改变全局顺序，任务仅独立保存勾选项。「恢复本任务默认勾选」重置当前任务的选择，「恢复默认排序」还原保存的排序基准，均先形成草稿；**点击「保存上下文设置」后下一轮生效**。切换任务、来源往返和保存失败保留草稿，旧任务独立顺序只归档，不再提供恢复排序继承。

通用资料按本轮场合读取，待细化活动、来源原文或日记正文等专用资料只使用本次明确输入，缺失就跳过。勾选不启用模块、不改变日期和私人场合筛选，保存时不触发新闻、搜索、其他任务或 QQ 发送；实际相关记忆召回可调用模型理解检索词；未勾选记忆不强化，不影响其他已选资料的关联去重。“当前阶段想法”默认仅活动细化勾选，可供其他任务自行选择，始终只提供自然语言。在途工具调用继续使用原布局及资料。所有临时资料无论放 system 还是 user 都不写入宿主聊天历史，原消息、媒体及其他插件内容保留；①展示同次位置与顺序，②可对照真实 HTTP 输入。布局版本 4 保存全局顺序、默认基准和任务勾选，初始化、重载和旧备份导入共用幂等转换；备份携带这些配置，旧调用及旧快照按原版解释，旧模板不改写。

## 记忆、备份与按钮

「记忆与画像」按自身与 QQ 人物档案、属性、场合、保留状态筛选，支持搜索、编辑、重要标记、删除和版本查看。稳定画像可按权限共用，具体私聊约定和衍生内容继续保留场合。

**「08 系统与数据 → 维护与诊断 → 整理旧记忆」**会淡化普通旧记忆、归档低强度记录并保留重要记忆，不调用 AI、不发送消息。关闭模块保留数据，重新开启后按当前规则继续。

导出备份含配置、生活、记忆及调试等管理员资料，可能含私人内容和配置凭据，请保存在可信位置。导入合并当前缺失记录，不覆盖已有 ID、防重记录和较新的数据，并将全部业务模块关闭；检查后再启用。

## 验收顺序

1. 先试跑日程大纲请求，核对 10 个活动与完整原始 JSON；再试跑细化，检查阶段文案、本次要求和全不安排／多类安排。当前想法默认仅细化勾选，并验证其他任务主动勾选和取消后的变化；插件提供的各类请求不含内在数值或机制，试跑不扣值或记为行动开始。
2. 用正式未开始活动和测试白名单，验证细化采用、新闻→搜索→聊天、上下文、免打扰及发送记录；每轮只抽选一个合格群或私聊目标，向 AI 明确目标类型、名字与接收范围，失败不另抽，真实发送不记为已经得到回复。
3. 检查私聊约定更新和不同群/私聊隔离；从日程、记忆、日记和消息各自核对。
4. 分别测试真实新闻、宿主搜索、和风和 B 站，核对作者日期、来源及失败记录；日报与日程次数独立。
5. 测试在线增长、人工修改、阶段拆分与删除、实际开始扣值和失败不退；验证数值不足仍执行、每轮单目标聊天只扣一次。重新细化、修改大纲、生成失败及唯一自动重试保持原边界；重复重生成不重置当前值和执行记录。
6. 测试关闭模块、重载、重启和跨日，确认不重复、不集中补发；再验证旧日程转换、模板备份和恢复旧备份，私人场合及旧执行记录继续保留。

在独立开发环境运行 `python -m pytest -q`、`python -m ruff check main.py living_world tests scripts`。导航与纯排序检查使用 `node tests/ui_navigation.cjs`，页面测试使用 `node tests/ui_smoke.cjs`，需要可用 Playwright 和 Edge。自动化与真实联调分别记录，见[交付与验收记录](03-delivery-and-validation.md)。
