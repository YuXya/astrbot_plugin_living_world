# 0.2.3 安装与测试说明

本插件支持 **Python 3.12、AstrBot `>=4.27.5,<5`**，使用 OneBot QQ / `aiocqhttp`。本轮自动化环境为 Python 3.12.14、本地 AstrBot 4.28.0-beta.1；4.27.5 已核对官方发布标签源码，真实环境联调另记。

## 安装与升级

1. 在 AstrBot 插件管理导入 `astrbot_plugin_living_world-0.2.3.zip`；或将目录放到 `data/plugins/astrbot_plugin_living_world`，根目录直接包含 `main.py`、`metadata.yaml`、`requirements.txt`、`living_world/`、`pages/`。
2. 使用 **AstrBot 实际运行的 Python 环境**安装 `requirements.txt` 中尚未安装的依赖，再加载或重载插件。
3. 在插件卡片打开 **Plugin Pages**。`/living_world` 只显示插件运行状态；配置、白名单和调试均在页面操作。
4. 升级前可在「数据与高级操作」下载备份。升级保留旧记忆、白名单、当天已有日程、执行和发送记录；不会因为升级重新生成当天日程，新配额规则用于下一份正式日程。

生活和记忆无需安装 private_companion 或 Angel Memory。B 站能力依赖已启用的 `astrbot_plugin_bilibili_ai_bot`，要求 `search_bilibili`、`watch_video`、公开记忆 API v3；其账号、视频解析和模型由该插件自行配置。

配置与数据统一保存在 AstrBot 插件数据目录的 `astrbot_plugin_living_world/living_world.sqlite3`，不在代码目录。Plugin Pages 是唯一配置入口，没有 `_conf_schema.json`。

**接入和日程验证：**升级并重载后，在白名单点击「检查会话与历史」。沿用默认人格的会话应显示实际人格和来源；无需重建。确认「日程生活」「被动回复」「调试记录」已开启，发送“现在日程是什么？”，查看最近实际注入及对应调试记录。在②API 原始请求里搜索“当前时间”“当前活动”“今日日程”，并核对具体内容。缺少日程或模块关闭会提供中文说明。

## 首次配置和白名单位置

1. 打开「角色、模型与模块」，绑定一个 AstrBot 人格，填写角色与世界资料、时区和初始状态。模型留空沿用宿主，也可设置默认模型及业务覆盖。
2. 进入左侧 **「聊天对象与白名单」**，点击「添加聊天对象」，填写 **QQ 连接、群聊／私聊、号码、启用、权重**，点击「保存聊天对象与限制」。首页「今日生活」顶部和「日程与行动」参数卡也能直达。
3. 表单自动生成完整会话 ID。原有 UMO 配置继续兼容；如需排查，目标会话中的 `/sid` 可查看宿主实际 UMO。不要把群号当成 QQ 连接 ID。
4. 让所选目标会话在 AstrBot 中使用同一人格。白名单按实际目标识别，记忆与人格按真实会话处理；开启 `unique_session` 时保留宿主的用户与群会话边界。
5. 未聊过的对象也可接入，点击「检查会话与历史」查看人格与历史状态；不创建空会话。群聊无需开启宿主群历史，从新收到的消息积累观察；已有宿主群历史可初始化窗口。使用本插件群聊插话时关闭宿主概率回复，否则插件暂停插话避免双重响应。
6. 保存抽选数量、冷却、每日上限和免打扰。权重影响随机抽中概率，不是内容相关性排序；一次抽选不重复选中同一目标。
7. 主动社交、插话和外部能力默认关闭，先配置明确的测试目标再启用。未绑定有效人格时插件不自动行动。

页面是 AstrBot 管理员视图，可以查看所有场合；聊天中的召回仍按所属场合过滤。不要将管理页面的完整内容直接分享给普通聊天对象。

## 日程参数和今日调整

在「日程与行动」设置生成时间、活动数、新闻活动数、搜索活动数、主动聊天活动数。默认 **06:00 / 10 / 2 / 2 / 3**。数量表示计划机会，不保证最终调用或消息发送成功。

AI 返回 JSON；活动包含起止时间、内容、地点、睡眠状态及 `actions.news/search/social`，每个行动包含 `enabled`、`intent`、`at`。每类标记数量必须合格，允许不同标记落在同一活动。执行顺序为新闻、搜索、聊天，聊天文本在执行时才生成。

保存生成参数不会调用模型或改写今天已有日程，默认下一天生效；若要立即用于今天，保存后点击「重新生成日程」。「编辑」或「批量调整未来活动」只处理尚未开始的活动，并保持原活动数和行动配额；需要交换标记时用批量调整。已经执行的记录不能通过编辑重放。

**「重新生成日程」**仅支持今天，有无旧日程均可使用，不受默认生成时间限制。先保存参数，再确认调用模型；使用本次操作开始时已保存的参数和模板重新生成今天整份计划，包括已经开始的安排。新结果通过数量与时间校验后立即采用，当前时间线、统计和聊天日程上下文切换为新版本；生成失败、取消、跨日或模块关闭时保留旧日程。

重生成会等待正在执行的日程轮次结束，生成期间暂停日程推进并禁止活动编辑、细化和重复提交。**新版本尚未到时的新闻、搜索、聊天标记照常执行，每个标记一次**；采用时已经到时的标记跳过。反复重生成会增加当天计划机会，但已有真实行动不会撤销，白名单、发送次数、冷却和免打扰仍然生效。

「正式日程生成档案」保留当前版本的参数、完整输入快照、模型生成文本和采用结果；下方折叠的历史版本另存替换前的活动及实际执行记录，可查看、下载和跳转到关联 API 记录。历史档案不随调试清理删除；恢复旧备份也不会让已退役活动重新执行。其他日期仍请用调试试跑。

独立随机空闲阅读、搜索和临时主动联系不再运行，旧的日程外主动联系入口不发送消息。被动回复和群聊插话仍独立控制。

## 内容来源

在「内容来源」保存配置，在「新闻、搜索与日记」查看事实、感想和历史记录。

| 来源 | 默认与配置 | 操作说明 |
|---|---|---|
| 新闻 | BBC 中文、Google 新闻中文、Solidot、Hacker News、MIT Technology Review、Ars Technica | 各行可改名称/地址、启停；「恢复默认新闻源」恢复六路配置，保留历史。AI 先从候选选一条，再读取并写感想。 |
| 搜索 | 沿用 AstrBot 的网页搜索开关和服务配置 | 先在宿主配置可用搜索服务。无需在插件里填写工具名、参数名或另一套密钥。 |
| 和风天气 | 地点、API Host、认证方式、凭据 | 地点可填城市名、城市 ID 或经度,纬度；API Host 填控制台专属域名，不填接口路径。支持 API Key 和已签发 JWT。 |
| B 站 | 固定 Bilibili AI Bot，显示依赖状态 | 提供搜索、完整 BV 号观看、公开视频记忆读取。缺少或停用依赖时，对应能力跳过。 |
| AI 日报 | 黑鸦 Heya UID `3706929260006322` 默认 12:00；橘鸦 Juya UID `285286947` 默认 23:00 | 可改时间与来源设置、逐路启停或恢复默认；每天各执行一次，不占日程或新闻配额，不额外聊天。 |

天气先解析地点，再读取和风实时天气。自动刷新成功后间隔 90 分钟，失败后退避 15 分钟；改变配置可重新尝试。**天气不会调用模型。**「测试天气连接」使用已保存配置，真实访问和风，但不写正式见闻、日程或记忆。

B 站日报通过只读视频信息确认作者和当天发布日期，不能确认时标明原因并跳过。搜索不代表观看；读取旧视频记忆会明确标记。插件不调用 B 站完整自主浏览、点赞、投币、收藏、关注、评论或私信流程。

「新闻、搜索与日记」里的手动读取区提供明确按钮：读取新闻并写感想、搜索并保存见闻、读取天气并保存、搜索 B 站视频、观看指定视频并保存、读取公开视频记忆。这些操作会真实调用来源、必要时调用模型并保存正式见闻，**不会主动发送 QQ**，也不会篡改计划行动的防重记录。

标题/订阅摘要、网页正文、搜索结果、视频分析与旧记忆分别标明阅读依据。获取失败不写成功见闻；模型整理失败仅保留已取得证据，感想留空，标记部分完成。

## 调试：AI 到底收到了什么

进入 **「调试与调用记录」**，每条记录固定四项：①上下文与信息来源、②API 原始请求、③API 原始返回、④回复阅读版。默认保留最近 10 轮完整聊天、后台每类 10 次完整调用，重试和子调用一起保留；可调整数量、按类别筛选与清理。

第二、三项来自 DeepSeek/OpenAI 兼容 Chat Completions 与 Responses 的实际 HTTP 正文，提供独立复制下载。多次请求通过下拉切换，收发一一配对；流式返回保留 SSE 原文，阅读版另行合并。认证凭据隐藏，未知参数和返回字段保留。未适配或未取得原文明确标注，不使用 Provider 参数代替。

四项仍通过按钮选择。第一项的来源按单列显示，默认展开，可分别收起；第二、三项默认提供 JSON 缩进与正文换行，也可切换原文。格式化只影响页面阅读，复制和下载始终保留保存的原始正文。

格式化 JSON 中的对象和数组默认展开，左侧小箭头可分别收起，另有“全部展开”“全部收起”。折叠状态按记录、请求及收发方向分别保留，正文变化时重置；收起后的复制下载仍包含完整原文。

第一项提供同次组装的来源和实际注入文本；第四项提供回复、推理、工具、用量、结构化结果和发送状态。旧日志标为“旧版快照，非 API 原文”。SDK HTTP 重试分别记录，第三方插件内部请求不捕获。完整说明见[聊天上下文与调试指南](04-chat-context-and-debug.md)。

清理不删除正式日程、记忆、群观察或发送防重。正式日程另存生成输入快照、模型生成文本和采用结果，可跳转关联调用；调试清理后不能再恢复对应 HTTP 原文。

## 隔离试跑与模板

1. 从某条模型记录建立测试请求，或选择任务和场合后点击「从当前配置建立测试请求」。这一步不调用模型。
2. 选择「组合模板与动态上下文」时，编辑 JSON 的 `template` 与 `dynamic_context`，试跑时重新组合提示词；旧 `prompt` 只是预览。选择「直接编辑完整 prompt」时，JSON 的 `prompt` 才是实际发送内容。
3. 两种模式都可编辑本次 `system_prompt`、`contexts`、`provider_id`、`model`、`parameters`。文本以及 `image_urls`、`audio_urls` 可供模型测试；包含非空 `extra_user_content_parts` 或 `tool_calls_result` 的特殊记录会明确拒绝直接试跑，请把需要的文字资料整理进 `contexts`。
4. 点击「仅调用 AI 试跑」会真实调用模型，可能产生费用，保存测试调试结果；**不执行工具、不发送 QQ、不改正式日程、记忆或生活数据**。
5. 「各任务提示词模板」单独保存公共任务指令，可恢复默认。试跑 JSON 不会自动保存到公共模板；不要把私人记忆、某次活动或整个请求粘进公共模板，动态内容由每次调用注入。

试跑适合检查日程 JSON 和提示词，不是 QQ 发送验收。需要真实行动验收时，使用正式日程中的未开始测试活动和已配置测试白名单。

## 记忆、备份与按钮

「记忆与人物」可编辑、合并和删除记忆；更新可能真实调用模型核对所属场合未来安排，旧内容不会继续作为有效记忆。姓名、兴趣等稳定人物认知可共用，具体私聊约定及衍生记录继续保留场合。

**「数据与高级操作 → 整理旧记忆」**会淡化普通旧记忆、归档低强度记录并保留重要记忆，不调用 AI、不发送消息。关闭模块保留数据，重新开启后按当前规则继续。

导出备份含配置、生活、记忆及调试等管理员资料，可能含私人内容和配置凭据，请保存在可信位置。导入合并当前缺失记录，不覆盖已有 ID、防重记录和较新的数据，并将全部业务模块关闭；检查后再启用。

## 验收顺序

1. 先试跑日程请求，核对 10 个活动与 2/2/3 标记、重叠标记和完整原始 JSON。
2. 用正式未开始活动和测试白名单，验证新闻→搜索→聊天、上下文正确、免打扰及发送记录；真实发送不记为已经得到回复。
3. 检查私聊约定更新和不同群/私聊隔离；从日程、记忆、日记和消息各自核对。
4. 分别测试真实新闻、宿主搜索、和风和 B 站，核对作者日期、来源及失败记录；日报与日程次数独立。
5. 测试关闭模块、重载、重启和配置改变，确认不重复、不集中补发；再验证备份恢复。

在独立开发环境运行 `python -m pytest -q`、`python -m ruff check main.py living_world tests scripts`。页面测试使用 `node tests/ui_smoke.cjs`，需要可用 Playwright 和 Edge。自动化与真实联调分别记录，见[交付与验收记录](03-delivery-and-validation.md)。
