# 记忆与上下文边界

## English Summary

This document makes AstrBot the sole owner of raw messages, conversation history, and session isolation. Message content and temporary ContextBundles are session-scoped; opaque target references and delivery controls are restricted operational data. A proactive send may produce a new, privacy-disconnected AI-life root fact containing no target, session, or generated text.

## 目的

Living World 要让同一个 AI 拥有连续生活，又不能把“AI 的连续性”误做成“所有用户对话互相可见”。本文件定义 `memory`、`conversation`、AstrBot 原生会话和其他模块之间不可越过的数据边界，是实现、评审和隐私测试的依据。

## 不可破坏的原则

1. AstrBot 是原始消息、消息记录、会话标识和会话隔离的唯一事实源。
2. 本插件不复制消息正文，不建立第二套聊天历史数据库，也不自行合并私聊、群聊或平台身份。
3. 全局共享的是 AI 自己经历的生活事件，不是任何会话中的用户消息、用户画像或对话摘要。
4. 对主动链路，`conversation` 只能在 `proactive` 已选定目标后逐个读取该目标的 AstrBot 会话正文，并只在本次处理期间组装上下文；禁止批量读取候选会话正文。
5. 动态生活上下文只做临时注入，不回写 AstrBot 历史，不伪装成用户或助手曾经说过的话。
6. 每类持久数据只有一个写入所有者；其他模块通过版本化消息请求或订阅读取投影。

## 数据所有权

| 数据 | 唯一所有者 | 可否持久化 | 使用边界 |
|---|---|---:|---|
| 原始消息、附件、引用、AstrBot 聊天历史 | AstrBot | 由 AstrBot 决定 | 插件只按当前会话、当前请求读取 |
| AstrBot 会话键、原始路由及其隔离关系 | AstrBot | 由 AstrBot 决定 | 插件不得重映射或跨会话合并 |
| 消息内容、摘要、由消息推断的信息与临时 `ContextBundle` | `conversation` 仅临时处理 | 否 | `session_scoped`；只沿单目标本次生成链路使用，结束即释放 |
| AI 的身份与叙事世界设定（含叙事地点目录） | `world` | 是 | 通过 `world.*` 事件或只读查询提供；不含现实天气查询位置 |
| AI 的当前生活状态（含当前活动中的叙事位置） | `state` | 是 | 不包含用户消息正文；不保存现实天气查询位置配置 |
| AI 的生活事件账本 | `memory` | 是 | 只记录 AI 所有的事件与合规来源摘要 |
| 现实天气查询位置（经纬度、城市 ID、时区关联）与天气观察 | `environment` | 按模块策略 | 与 `world` 的叙事地点分离；进入记忆前先最小化并保留来源 |
| 新闻、搜索与 B 站公开内容观察 | `exploration` | 按模块策略 | 进入记忆前先最小化并保留来源 |
| opaque target reference、会话类型/可达性、免打扰、退出、权重与频控 | `audience` | 最小必要时 | 受限 `operational`；仅用于枚举、资格、排序和投递，不含消息正文且不得进入生活记忆 |
| 路由结果与脱敏投递审计 | `proactive` | 最小必要时 | 受限 `operational`；不保存完整会话派生文本，按访问、导出和删除控制处理 |
| 管理页只读投影与操作审计 | `admin` | 是 | 不直接修改其他模块数据表 |

`session_scoped` 只包含某个会话的消息内容、摘要、由其推断的信息，以及本次生成使用的临时 `ContextBundle`。脱离消息内容且确需持久化的 opaque target reference，以及免打扰、退出、权重、频控、可达性、路由结果和脱敏投递审计，属于受限 `operational`，不是聊天记忆；它们只能由 `audience`、`proactive`、`admin` 按最小必要原则访问，并受导出、删除和权限控制。任何 operational 目标数据都不得进入 AI 生活账本或携带跨目标内容。

## AI 生活记忆的准入规则

可以进入全局 AI 生活账本的内容包括：

- 已发生的日程活动、状态变化、地点或世界事件；
- 经标准化的现实天气观察；
- 带来源、时间和可信度的新闻、搜索或 B 站公开内容摘要；
- `proactive` 在主动行为完成后发布的、符合下述隐私断开规则的最小 AI 行为事实；
- 系统生成且明确属于 AI 自身的反思、日记或阶段总结。

不得进入全局账本的内容包括：

- 用户消息原文、附件内容、逐字引用或完整对话摘要；
- 从某个群或私聊推断的用户秘密、偏好、关系、情绪或身份映射；
- 为了方便召回而复制的 AstrBot 历史记录；
- API 密钥、Cookie、鉴权头、管理口令或模型内部推理；
- 缺少来源标记、无法区分事实与生成内容的外部观察。

1.0 完全禁止把 `session_scoped` 内容直接或间接提升为 `ai_life`。即使一次对话看起来促成了 AI 的决定，也不得把原文、摘要、去用户化改写、抽取结论或其他会话派生内容写入全局账本；也不得通过删除会话字段、改写措辞或重置因果链来伪装提升。由 `world`、`planner`、`state`、`environment` 或 `exploration` 独立产生、能在没有该会话时成立且不含会话 payload/因果标识的 AI 生活事实，才可按准入规则入账。任何会话到全局记忆的提升能力都必须作为未来独立提案，默认关闭，并经过新的隐私 ADR；不属于 1.0。

主动行为完成后，`proactive` 可以发布自己 family 的 `proactive.life_action_completed`，作为隐私断开的最小 `ai_life` 新根事实，供 `memory` 记录“AI 做过一次什么动作及其结果”。这不是 session 提升，必须同时满足：

- payload 只含动作类型、结果、发生时间和源生活事件引用；
- 不含目标/会话标识、opaque target reference、消息文本、摘要、推断、路由结果、投递幂等键或任何可反查目标的标识；
- `causation_id` 为空，使用全新的 `correlation_id` 与 `trace_id`，不得复用 `session_scoped` 生成/投递链路的 correlation、causation 或 trace；
- 内容来自主动动作本身及既有源生活事件，不读取、不摘要也不变换会话内容；
- 目标引用和逐目标发送结果只保留在受限 `operational` 审计中，不随该事实进入 `memory`。

该生活回写还必须满足以下幂等与粒度规则：

- 每个 `proactive` 候选最多发布一条目标无关的聚合 `ai_life` 事实；不得按目标分别发布生活事实，也不得因一个候选触达多个目标而生成多条账本记录。
- 聚合事实不得包含目标数量、逐目标结果明细、逐目标 delivery key 或其可逆/可关联变体；“结果”只能表达该候选对应 AI 动作的目标无关聚合结果。
- 首次创建该回写时，`proactive` 必须生成并持久化一个隐私安全的稳定幂等身份。该身份不得由目标、会话、opaque target reference 或任何逐目标 delivery key 推导，也不能用于反查这些数据。
- 同一候选的失败重试、进程重启和事件重放必须复用该稳定幂等身份；`memory` 以它防止重复入账，不得用新的消息身份绕过防重。
- 稳定幂等身份的具体字段、生成算法、持久化位置、聚合结果枚举与完成时机由 `proactive`/`memory` 专题契约和 ADR 决定，本总计划不提前锁死。

## AstrBot 读取端口

`conversation` 使用两种严格分离的 AstrBot 读取端口；二者不得通过同一个“查询任意会话”接口实现：

1. **最小会话枚举端口**：在建立对象池和选择目标前，只枚举 opaque session reference、会话类型与当前可达性。结果标记为受限 `operational`，不返回昵称画像、消息正文、摘要、最后消息片段或由正文推断的信息。`audience` 只能用这些引用结合自身免打扰/退出/权重规则计算资格与排序。
2. **单目标历史端口**：仅当 `proactive` 已选定一个目标并发起该目标的个性化请求后，`conversation` 才能用对应 opaque reference 读取一个 AstrBot 会话。每次只读取一个会话，返回 `session_scoped ContextBundle`；禁止批量读取多个候选的正文、以排序为名预读历史或在目标间复用结果。

普通被动回复沿用 AstrBot 当前入站会话提供的上下文，不触发对象枚举。两个端口都不得复制 AstrBot 历史到插件存储；端口访问日志只保留不含正文的受限 `operational` 元数据。

## 单次上下文组装

`conversation` 按以下顺序处理一次回复或主动个性化请求：

1. 被动回复接收 AstrBot 提供的当前会话上下文；主动个性化则在目标已选定后通过单目标历史端口取得该会话的临时历史视图。
2. 通过消息总线分别请求 `world` 身份/设定、`planner` 当前与近期计划的最小投影、`state` 当前状态、`memory` 合规 AI 生活片段，以及按需的 `environment` 环境投影；请求必须携带 `correlation_id`。
3. 对数据做范围校验、长度预算、来源标注和敏感信息过滤。
4. 生成一个结构化、只读、带作用域的临时上下文包。
5. 将生活上下文作为明确标记的附加区段交给本次 LLM 调用。
6. 调用结束后释放上下文包；只允许相关所有者记录业务结果，不保存拼装后的提示词。

主动消息必须逐目标重新执行以上流程。禁止批量预读候选正文，也禁止先为目标 A 拼装上下文，再替换称呼发送给目标 B。

## 作用域与泄漏防线

- 会话作用域完全沿用 AstrBot 提供的会话键；插件不得猜测两个会话是否属于同一个人。
- 群聊上下文不得进入私聊上下文，私聊上下文也不得进入群聊上下文，除非 AstrBot 本身把它们定义为同一会话；插件不增加额外合并。
- 全局 AI 生活事件可以在多个会话中被提及，但表达时不得包含其来源会话或可识别用户的线索。
- 外部页面、新闻、搜索结果和视频文本均视为不可信输入；它们只能作为带来源的数据，不得覆盖系统边界、人格设定或工具权限。
- 查询超时、作用域不明、数据版本不兼容或脱敏失败时，必须少注入或不注入，不能回退到跨会话搜索。

## 删除、导出与审计

`0.0.1` 不创建任何业务存储。引入持久化时必须同时交付：

- 按数据所有者划分的保留周期和删除入口；
- AI 生活账本与主动审计的可读导出，不包含 AstrBot 消息副本；
- 删除后的索引清理、缓存失效和事件幂等行为；
- 能说明“何时、因何事件、由哪个模块写入”的来源字段；
- 日志脱敏规则，确保正文、密钥和临时提示词不进入普通日志。

## 验收场景

- 在群 A 提供一个独特秘密，随后在群 B、私聊和主动消息中均不能召回该秘密。
- 当前会话读取失败时，回复可降级为仅使用 AI 生活上下文，且不得扫描其他会话。
- 对象池建立前只能看到 opaque reference、会话类型和可达性；选择目标后每次只能读取一个目标的 `ContextBundle`。
- 同一个全局天气事件可影响多个会话中的 AI 状态，但不能暴露最初触发它的会话。
- 主动发送完成后的 AI 生活回写是新的隐私断开根事实；每个候选最多一条，其 payload 只出现动作类型、目标无关聚合结果、时间和源生活事件，不出现目标数量、逐目标明细/键、会话、文本或原投递链路标识；处理过程复用隐私安全的稳定幂等身份，重试与重放不重复入账。
- 重启后可恢复 AI 生活账本；任何临时会话上下文包都不能恢复。
- 导出插件数据时不出现原始消息、附件、完整对话摘要或拼装后的 LLM 提示词。
- 对重复生活事件进行幂等处理，不因重放制造多份记忆。
