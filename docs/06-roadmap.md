# 路线图与阶段门禁

## English Summary

Living World advances through contract, life-simulation, perception, proactive-action, administration, beta, and 1.0 gates. Each phase has explicit entry and exit criteria. Detailed algorithms and storage schemas remain deferred to module ADRs rather than being guessed in this roadmap.

## 路线图原则

- 每个阶段先冻结跨模块契约，再并行实现，最后通过可重复的集成门禁。
- 外部服务全部可选且可降级；天气、搜索或 B 站不可用不能阻止插件加载或破坏既有生活状态。
- 主动发送直到生活、感知、记忆和隐私门禁全部通过后才启用，并始终保留总开关、免打扰和审计。
- 版本号遵循语义化版本；阶段门禁不强制对应每一个中间版本号。
- 状态数值、数据表、天气字段、新闻源、重试次数、记忆算法和 LLM 预算由模块专题 ADR 决定，本文件不提前锁死。

## 各阶段实施重点

### `0.0.1`：计划文档与空骨架

只创建计划指定的根文件和文档。`main.py` 只做装配入口与健康检查，不创建数据库、业务配置、后台任务、页面或真实主动消息。仓库公开但不提交 AstrBot 插件市场。

### 基础门禁：先让并行开发可控

P0 冻结消息信封和兼容规则，P1 提供内存总线、虚拟时钟与受监管任务模型，P8 建立契约和架构守卫。所有后续团队收到同一套事件夹具，不依赖尚未完成的邻接模块。

### 生活门禁：形成“AI 今天真的在生活”的闭环

世界设定提供稳定身份和规则，日程只表示计划，状态只表示实际发生，天气作为现实环境证据，记忆只记录 AI 所有的生活结果。此阶段可以生成预览和诊断，但禁止真实主动投递。

### 感知门禁：让观察有来源且可失效

新闻、搜索和 B 站探索结果必须先裁剪到业务所需最小内容，标注来源、抓取时间、内容时间、适用范围和可信度，并与系统指令、人格及工具权限隔离。完成这些处理后，`exploration` 才能通过 AstrBot 正式 LLM 能力进行受控阅读或摘要，并输出仍保留来源的 observation；外部文本始终是不可信数据，不能提升权限或改写人格。B 站首期仅使用被明确声明为公共、只读且版本可协商的能力。

LLM、模型提供方或对应能力不可用时，模块必须发布可诊断的明确降级状态，跳过依赖模型的阅读/摘要，不得伪造 observation，也不得阻断其他来源继续采集或世界、日程、状态与记忆构成的生活闭环。具体模型路由、提示设计、输入/输出预算、成本上限和失败策略由探索专题契约与 ADR 决定，本路线图不提前锁死。

### 主动门禁：最后接通发送

生活或感知事件先触发 `proactive` 创建候选；`audience` 再独立负责对象资格、免打扰、基础权重与本次候选评分，并选择前 N。选定后，`conversation` 为每个目标逐一读取其 AstrBot 会话并组装上下文，`proactive` 再逐目标生成、复核和投递。任何步骤失败都留下可解释审计，但不通过重复发送补偿；生活账本回写按候选聚合，不能按目标重复记录。

### 管理门禁：让所有行为可看、可停、可恢复

Plugin Page 展示世界、日程、状态、环境、探索、记忆、对象池和主动审计的只读投影；修改通过版本化管理命令完成。必须提供总停用、外部能力状态、导入前验证、导出和故障诊断。

## 发布依赖图

```text
基础：contracts ──> kernel ──> world / planner / state
感知：kernel ───────────────> environment / exploration

world + planner + state + environment + exploration ──> memory
world + planner + state + memory + [按需 environment] ──> conversation

生活/感知触发
  ──> proactive 创建候选
  ──> audience 完成资格、权重与前 N 选择
  ──> conversation 对已选目标逐个组装上下文
  ──> proactive 逐目标生成、复核与投递
  ──> OneBot

所有稳定管理命令 ──> 各目标领域；admin 汇总生命周期/投影 ──> 0.9.0 ──> 1.0.0
```

`proactive` 独占候选、内容生成与投递，`audience` 独占对象资格、权重和排序；二者不得互相写入对方状态。`conversation` 的世界/计划/状态/记忆与按需环境投影依赖可以提前用模拟事件联调，但只有 `audience` 返回已选目标后才能逐个读取会话正文。`admin` 可以使用模拟投影提前开发，但管理门禁只能在真实模块管理命令稳定后关闭。`proactive` 可以在 dry-run 模式联调，但真实发送必须等待隐私和 OneBot 验收。

## 延后决策清单

以下事项必须在开始对应实现前由所有者提交 ADR，且不得由实现者临场选择：

- 日程生成策略、状态维度、冲突处理和跨日规则；
- 持久化引擎、表结构、迁移、备份、恢复和保留周期；
- 和风天气的具体端点、字段映射、缓存与配额策略；
- 新闻源、搜索能力发现和 B 站公共接口版本；
- 记忆筛选、压缩、检索、删除和来源可信度；
- 对象评分、前 N 上限、免打扰、频控和未回应降速；
- LLM 路由、提示词预算、失败降级和成本上限；
- Plugin Page 的权限模型与敏感配置展示规则。

## 1.0 明确不做

1.0 不建立聊天历史副本或额外消息隔离，不做多人格生活，不承诺全平台适配，不跨会话共享用户记忆，不依赖第三方插件私有方法，也不实现 AI 与其他 LLM 的持续自主聊天。新增这些方向必须独立立项，不能以“顺手兼容”进入 1.0。
