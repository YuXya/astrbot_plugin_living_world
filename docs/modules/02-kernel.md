# 模块卡：`kernel`

## English Summary

`kernel` provides the in-process message bus, clock, lifecycle, supervised tasks, and persistence primitives. It transports validated messages but does not make domain decisions or own domain data.

## 目标

提供模块化单体共享的可靠运行底座：版本化消息路由、请求/响应关联、可替换时钟、受监管后台任务、插件生命周期、取消、恢复钩子和持久化基础设施抽象。

## 非目标

- 不决定 AI 的世界、计划、状态、记忆、天气、探索或主动行为。
- 不把业务数据集中写入“内核数据库”。
- 不解释或修改业务载荷，不为失败事件猜测补偿动作。
- 不直接发送 OneBot 消息或调用 LLM、天气、新闻、搜索、B 站服务。

## 所有权

P1 内核工程师拥有实现与运行语义；P0 会签公共装配和契约影响；P8 会签并发、恢复和故障行为。

## 消费/发布的事件族

- 消费：`kernel.*` 中的生命周期管理、时钟调度请求，以及所有通过总线传输的已注册消息信封。
- 发布：`kernel.*` 中的生命周期状态、时钟 tick、任务状态、消息拒绝/死信诊断和请求超时响应。
- 仅运输：其他十一个业务事件族；运输不等于拥有或消费其业务语义。

## 允许修改范围

- 允许：总线、时钟、任务监管、生命周期协调、事务/存储基础抽象、恢复与内核诊断。
- 需要契约评审：信封校验、投递保证、顺序、重试、死信和请求超时的公开语义。
- 禁止：在内核添加模块专用表、业务分支、提示词或第三方服务适配。

## 模拟依赖

需要内存传输、虚拟时钟、确定性 ID 生成器、临时存储替身和可注入的任务失败器。不得以真实等待验证定时逻辑。

## 交付物

- 类型安全的进程内消息总线与订阅生命周期；
- 带 `correlation_id` 的请求/响应及超时取消；
- 虚拟/系统时钟接口和 tick 调度；
- 插件启动、重载、卸载时的受监管任务组；
- 每模块存储命名空间、事务与迁移基础接口；
- 并发、幂等、恢复和可观测性测试工具。

## 联调对象

P0 的 AstrBot 装配入口、所有业务模块、P8 的故障注入与架构测试。最先与 `contracts` 联调，再向其他团队发布稳定夹具。

## 验收门槛

- 重复订阅、重载和卸载不会泄漏任务、句柄或继续发布事件。
- 请求响应正确关联；超时、取消和迟到响应有确定行为。
- 重复、乱序、消费者异常和未知消息不会导致总线整体崩溃。
- 虚拟时钟可确定性推进跨日场景，测试不依赖 `sleep`。
- 业务模块存储彼此隔离，内核本身不拥有业务记录。
- 总线只接受 `contracts` 注册消息，并为拒绝提供可审计原因。
