# 上下文名称、分类用量与主动聊天 · 0.2.5

## 名称与入口

上下文名称统一采用「实际二级菜单：具体资料」。上下文排序、上下文用量、分类筛选、来源说明、新调用记录①及实际注入标题使用同一份目录。菜单路径仅出现在管理页面，不发送给模型。任务选择器和提示词模板保留「原任务标识（中文说明）」。

进入 **02 上下文与提示词**，顶部依次为「上下文排序、上下文用量、提示词模板、模型试跑、调用记录」。06 的存档面板改名为「近期见闻」，07 保留「记忆与人物、日记与笔记」。旧 `#memory?tab=usage` 自动定位到 02 的用量面板。

## 一套排序与每任务勾选

“调整范围”只切换当前任务的勾选项，所有任务显示同一完整资料列表，包含未勾选项。除只读人格及原始消息定位行外，每行均可勾选、拖动、上下移动和切换 system／user；在任何任务下调整都修改同一全局顺序。升级前已保存的全局顺序及角色位置是默认基准，旧任务独立顺序只归档。

「保存上下文设置」保存草稿，「恢复本任务默认勾选」还原当前任务默认选择，「恢复默认排序」还原排序基准；恢复均先改草稿。任务切换、来源往返、保存失败继续保留输入。初始选择沿用各任务既有资料，聊天的简版日程和新增回复要求按下述默认补入。

通用资料在任意勾选任务中按本轮场合读取；待细化活动、来源原文、日记正文等专用材料只使用当前任务明确提供的输入，缺失就跳过。勾选不调用新闻、搜索、额外模型或其他任务，不放宽模块、场合、日期及用量限制。“当前阶段想法”默认只在活动细化勾选，其他任务可自行勾选，始终只提供本轮命中的自然语言文案，不提供数值或机制。

## 独立用量

表中每类独立设置，普通类别范围 0—50，天气 0—1。0 只停止这一类自动注入，不删除存档，各类之间不借用额度。日记和笔记简报另有各自的最长字符，初始各 200，可设 50—1000；修改后，旧简报在下次注入时同样受长度限制。

顶部「恢复初始用量」将表单恢复到初始值，先形成草稿；点击「保存上下文用量」后生效，不改其他面板草稿。

顶部显示只读「配置合计最多注入 × 条」，随当前输入实时相加；初始合计 28 条。没有可编辑的记忆总上限或隐藏总限制。合计不含人格、日程、任务明确要求的原文、来源证据、回顾材料或宿主聊天历史，实际注入可能更少。

记忆先按保存的日记／笔记来源识别简报，再识别人物认知，其余按结构化记忆类型分类，不根据中文标题或正文猜测。每类先按模块、场合、人物及日期过滤，再按相关性排序、明确来源关系去重和限量。经历及见闻取最新可用记录；没有明确关联的相似正文不被认作同一个事件。仅强化实际采用的记忆；未勾选的类别不强化，也不参与其他已选资料的关联去重。例如取消近期经历后，同源记忆仍可在已勾选的记忆区召回。

新闻、搜索、B站、AI日报在排序中合为「近期见闻：综合见闻」，四类按时间合计取最新记录，内部保留「近期见闻：新闻」等来源标签。天气独立取最新可用记录。数量文案分别使用「每次读取数量」「上下文最多条数」「列表每页条数」；读取多少条、注入多少条和管理页显示多少条是三个独立设置或规则。

普通聊天、主动聊天、插话和后台任务的自动召回采用这套独立额度。日记回顾的当日事件、简报任务明确指定的完整原文及来源整理的原始证据继续遵守各任务规则，不占自动召回额度。记忆提炼所需的旧记忆标识仅用于该提炼任务，普通聊天不会因此增加内部标识。

## 来源索引、草稿和记录

上下文排序的每块、用量设置的每行都提供「来源」。面板说明用途、生成来源、准确菜单路径和确有关系的模板；记忆分类、日记／笔记类型及四类见闻可直接选中，对应用量字段可高亮定位。返回按钮恢复原选择、草稿和滚动位置。

来源索引说明的是类别用途与管理入口，不表示某次历史调用实际采用了哪条原始记录。新调用记录①保存同次注入数量、采用上限、角色、顺序和文本；②③保存真实 HTTP 正文，④为阅读版。旧调用名称和原文保持原样。

草稿保存在页面内存。导航、对象切换、来源跳转和刷新不会丢失；保存只提交本面板负责的设置，失败保留输入，成功不清除其他面板草稿。关闭或重载仍提示未保存，不自动写入本地存储。布局、勾选与用量保存后下一轮生效，正式调用和组合试跑共用组装；每轮冻结顺序、选择、资料及回复文案，在途请求和工具后调用使用原快照。①仅列实际注入的资料，与②请求正文一致。

## 主动聊天目标

活动细化决定是否安排聊天；到执行时间，程序按白名单权重抽取 **一个** 合格目标，可以是一个群或一个私聊对象。沿用人格检查、免打扰、冷却、发送上限与防重。没有合格目标时不生成消息，已选目标失败后不自动换人。

白名单可填写「对话称呼（提供给 AI）」。模型收到「聊天白名单：交谈对象与场合」，保留会话类型及接收范围，私聊显示“目标名字：名称”，群聊显示“群聊名字：名称”。优先手填称呼，否则通过对应 QQ 连接只读昵称或群名；失败显示“未设置名字”，不回退 QQ 号、群号或群成员名。自动名称按连接和实际目标缓存，成功一小时、失败一分钟后重试，读取总超时两秒。名称本身的合法数字保留；号码继续用于管理、匹配和实际发送，不清洗聊天原文。群聊明确面向整个群，程序固定发送目标，AI 只生成正文。

该块可以排序、切换角色并跳到白名单。插话使用当前群；模型试跑使用显式选择的会话，不抽取真实目标、不发送 QQ、不修改业务数据。

## 三条日程与三份回复要求

“今日日程（完整）”和“今日日程（简版）”是两个独立资料行，同一任务最多勾选一种，也可全部取消。chat.group、chat.private、social.message 默认勾选简版，其他原本使用日程的任务保留完整版本。

简版先按角色时区今天、当前场合过滤，排除取消及退役活动，再选择上一条、当前条、下一条；没有当前活动时选择最近两条过去活动与下一条未来活动。最多三条，不足不跨日补齐。每条保留完整可见正文、时间、真实状态、地点和睡眠，失败或跳过如实显示，不调用模型摘要、不截短正文。两个版本来自同一次日程快照，管理页完整日程与正式执行记录继续保留。

「05 聊天与对象 → 回复与插话」分别编辑群聊、私聊、主动聊天三份回复要求，各自可恢复默认、留空关闭，最多 8000 字符。升级保留原群聊文案，新两份首次复制原文（包括空值），之后独立保存；新增资料行放在原群聊要求旁。默认分别用于 chat.group、chat.private、social.message，后者包含插话正文生成，插话判断默认不勾选。所有任务都可自行勾选三份要求，文案以独立指令形式按全局顺序注入，不写入宿主历史，工具后继续沿用本轮快照。

## 升级与备份

- 布局升级到版本 3：`order` 保存唯一全局顺序，`baseline_order` 保存恢复默认所用基准，`tasks` 保存各任务的勾选集合。旧全局顺序及 system／user 位置完整保留，简版日程插在完整日程旁，新回复要求插在群聊要求旁；旧任务独立顺序只归档，不再参与运行。更早版本先在原记忆位置展开七类、由旧新闻位置承接综合见闻，再转到版本 3。
- 独立 `context_usage` 保存稳定标识对应的条数和简报长度。旧记忆额度按 4:2:1:1:2 最大余数法分给前五类，同余按表格顺序；旧有效简报额度为旧总数与旧简报数的较小值，平均分给日记和笔记，奇数余量给日记。旧总数为 0 时七类继续关闭；旧字符数复制到两个新字段，旧多目标数转为 1。
- 原设置在转换前归档，转换与升级事务一同提交或回滚。新备份携带全局顺序、默认基准、各任务勾选及用量，初始化、重载和旧备份导入采用相同幂等转换；恢复仍关闭业务模块，无 SQLite 表结构迁移。
- 旧调用及自定义提示词不改写。旧布局快照试跑沿用旧版解释规则和快照材料，不套当前额度；直接编辑完整请求仍以显式输入为准。
