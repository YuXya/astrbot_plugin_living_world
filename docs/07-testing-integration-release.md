# 测试、联调与发布

## English Summary

Testing is contract-first and deterministic: modules use event fixtures, virtual time, and fake external adapters before end-to-end OneBot testing. The `0.0.1` release must prove a side-effect-free AstrBot skeleton from a fresh clone. Later releases add privacy, recovery, degradation, migration, administration, and proactive-send gates.

## 质量策略

测试目标不是证明“正常情况下看起来能用”，而是证明模块在重复、乱序、延迟、外部故障、重载和部分升级时仍保持边界。所有时间驱动逻辑必须支持虚拟时钟，所有外部服务必须有测试替身，所有跨模块行为必须可由事件夹具重放。

## 测试层级

| 层级 | 责任人 | 重点 | 是否允许真实外部服务 |
|---|---|---|---:|
| 静态与架构守卫 | P8 + P0 | 禁止跨模块实现导入、跨库写入、密钥入库、无版本事件 | 否 |
| 模块单测 | 各模块所有者 | 纯规则、边界值、错误映射、幂等 | 否 |
| 契约测试 | P8 + 生产/消费双方 | 信封校验、版本兼容、请求/响应关联、拒绝语义 | 否 |
| 模拟集成 | 邻接模块所有者 | 事件流、超时、取消、重复、乱序、重启恢复 | 否 |
| AstrBot 插件集成 | P0 + P8 | 加载、重载、卸载、命令、会话读取、配置生命周期 | 本地 AstrBot |
| OneBot 端到端 | P6 + P8 | 私聊、群聊、路由、免打扰、发送与错误回执 | 受控测试账号 |
| 外部适配冒烟 | P4/P5 + P8 | 和风天气、搜索、新闻、B 站能力协商 | 可选的受控测试环境 |
| 发布验收 | P0 + P8 | 新装、升级、回滚、文档、许可证和包体 | 仅明确列出的环境 |

线上凭据不得用于单测或普通 CI。外部冒烟失败若由服务不可用导致，可以标记环境失败，但对应降级测试仍必须通过。

## `0.0.1` 首次公开验收

首次版本只验收计划文档和无副作用骨架：

- `metadata.yaml` 可被目标 AstrBot 解析，插件 ID、目录名和仓库名均为 `astrbot_plugin_living_world`，版本为 `0.0.1`。
- `Main(Star)` 使用当前插件入口方式，不使用废弃的 `@register`。
- 插件可加载、热重载和卸载；重复执行生命周期操作不残留任务或句柄。
- `/living_world` 在 OneBot 私聊和群聊返回确定性的健康信息。
- 加载、调用命令和卸载均不创建业务数据库、聊天记录副本、后台任务、配置页或真实主动消息。
- 首批不出现空 `_conf_schema.json`、空 `requirements.txt`、Pages 或占位业务模块。
- README 明示 pre-alpha、尚无业务能力、MIT 与 clean-room 边界。
- 文档内相对链接可解析，12 张模块卡和 P0–P8 九张任务卡齐全，固定章节无遗漏。
- 发布包不包含 `.git`、缓存、虚拟环境、测试凭据或本机生成数据。

验收必须在远端全新克隆上再执行一次，不能只验证开发工作区。

### 首次 GitHub 建仓清单

- 本地仓库直接初始化为 `main` 分支，首批历史严格分为两次提交：先提交“可加载空骨架”，再提交“主程规划文档”。
- 在 `YuXya` 名下创建空的 public 仓库 `astrbot_plugin_living_world`；创建时不让 GitHub 自动生成 README、许可证或 `.gitignore`，避免与本地文件冲突。
- 推送 `main` 后配置仓库描述、相关 topics，并保持 Issues 启用。
- 为 `main` 配置分支保护或等价 ruleset；至少要求通过必要检查后才能合并，并阻止强制推送和删除受保护分支。若 GitHub 账户或仓库方案暂不支持该能力，P0 必须记录未完成项，不能把它标记为已通过。
- 从远端克隆到全新临时目录，重新执行元数据解析、加载、命令、热重载和卸载检查；验证结束后清除临时副本。

## 后续门禁测试矩阵

### 契约与内核

- 合法信封可路由，缺字段、未知事件、未知主版本和超限载荷被显式拒绝。
- 请求与响应使用正确 `correlation_id`；迟到响应不会污染下一次请求。
- 重复 `message_id` 不重复产生业务副作用，乱序事件按各模块策略处理并可诊断。
- 虚拟时钟可推进跨日、夏令时无关场景、暂停和恢复，不依赖真实等待。
- 任务取消、插件重载和卸载后没有后台协程继续发布事件。

### 生活、环境与记忆

- 同一计划活动不会因重复 tick 启动两次；计划与实际状态可以明确不同。
- 天气缓存命中、过期、限流、无定位、坏响应和服务中断均有确定降级。
- 外部观察保留来源和时间，提示注入文本不能变更权限或人格。
- AI 生活事件可持久、检索、压缩和删除；重放保持幂等。
- 群 A 的独特内容在群 B、私聊及其他目标的主动生成中不可见。

### 主动能力与 OneBot

- 对象池先排除未授权、免打扰、频控和不可路由目标，再对剩余目标排序并取前 N。
- 同一事件为每个目标独立读取 AstrBot 会话并独立生成；上下文和成品不能复用。
- dry-run 不调用平台；完整个性化文本仅可在受控、短时、明确授权的预览中显示，预览结束即释放且不得持久化。审计只保存脱敏元数据与确有诊断必要的最小摘要，不保存完整会话派生文本；总开关关闭时没有旁路。
- 发送超时、明确失败、未知结果和重试分别处理；未知结果不能无条件重发。
- 去重键跨重启有效，发送成功、拦截、放弃和失败均有审计与生活事件回写。

### 管理页面

- 页面只能调用公开管理命令和读取投影，架构测试应阻止其直接打开模块数据库。
- 未授权访问、会话过期、并发编辑、旧版本配置、导入坏数据和部分保存失败有明确反馈。
- API 密钥默认遮盖，导出不包含密钥、Cookie、原始消息或临时提示词。
- 总停用、模块状态、外部降级与主动审计在黑盒测试中与后端事实一致。

## 测试替身与夹具

P8 维护版本化事件夹具和最小场景库；模块所有者维护自身输入输出示例。至少提供：

- 可手动推进的虚拟时钟；
- 内存消息总线及重复、乱序、丢失、延迟注入器；
- AstrBot 当前会话读取替身，默认拒绝跨会话查询；
- 和风天气成功、限流、超时、字段缺失与过期缓存响应；
- 新闻、搜索、B 站能力存在、缺失、版本不兼容和恶意文本响应；
- OneBot 成功、明确失败、未知投递结果、限流和撤权响应。

夹具不得包含真实用户消息、真实 Cookie、API 密钥或从参考项目复制的受保护内容。

## CI 合并门禁

每个合并请求至少运行：格式与基础静态检查、文档链接检查、模块边界检查、模块单测、契约测试和许可证/秘密扫描。涉及持久化时增加迁移往返测试，涉及页面时增加构建与黑盒测试，涉及适配器时增加录制响应的离线测试。

测试环境的 Python 与 AstrBot 范围以 `metadata.yaml` 宣告的支持范围为准；扩大范围必须先在 CI 中验证。任何“允许失败”的作业都不得对应项目声称支持的核心平台。

## 候选发布流程

1. P0 冻结版本和契约，P8 生成可追踪的候选报告。
2. 从干净环境安装目标 AstrBot，再从远端仓库全新克隆插件。
3. 执行加载、命令、重载、卸载以及该版本对应的完整门禁。
4. 对升级版本执行备份、旧数据迁移、重启验证和回滚演练。
5. 核对 README、CHANGELOG、metadata、许可证、依赖清单、包体和敏感信息扫描。
6. 由 P8 给出质量结论，P0 最终放行并创建不可变标签。

`0.0.1` 只公开 GitHub，不提交 AstrBot 插件市场。达到市场发布阶段时，再依据当时的官方规范核验元数据、支持平台、包体和提交流程。

## 阻断与回滚

跨会话泄漏、绕过免打扰、重复主动发送、数据不可恢复、密钥泄漏、未知许可证内容或无法卸载的后台任务均为发布阻断项。发布后发现这些问题时，先关闭相关能力或回滚到最后一个安全版本，再修复；不得以日志提示代替保护措施。
