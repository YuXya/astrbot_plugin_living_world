# ADR-0002：所有跨模块交互经过版本化消息总线

> **English Summary:** Modules communicate only with versioned events, commands, queries, and responses on one bus. Direct service calls and shared database access across module boundaries are forbidden.

- 状态：Accepted
- 决策日期：项目初始化
- 决策人：P0

## 背景

十二个模块需要并行开发、独立降级和追踪因果。直接调用服务或共享数据库会把内部实现暴露给消费者，使测试、恢复和隐私审计依赖隐式约定，最终形成难以拆解的单体。

## 决策

1. 所有跨模块动作使用同一个版本化消息总线，包括事件、命令、查询、响应和失败通知。
2. 查询不得直接调用所有者服务；请求与响应通过 `correlation_id` 配对。
3. 业务模块只依赖 `contracts` 中的公共消息定义，不直接导入其他业务模块实现。
4. 每类数据只有一个写入所有者；消费者不得读取或修改其他模块的表、仓储和可变对象。
5. `main.py` 在装配时可创建实例和注册处理器，但不传递业务数据来绕过总线。
6. 十二个模块中的 `contracts` 只定义并验证契约，不发布或消费 `contracts.*`；其余十一个模块拥有运行时事件族。
7. 消息必须支持版本、因果追踪、隐私分类和幂等处理，细则见 [事件契约](../03-event-contracts.md)。
8. `admin` 受理管理操作后发布目标领域 family 的 `Command`；目标领域以自己的 family 返回事实或失败。`admin.*` 只用于管理操作生命周期、审计关联和只读投影。
9. 每个公共契约变更在修改定义或实现前，必须先更新现有契约 ADR 的变更记录，或新增/替代 ADR 并获 P0 接受；随后先补契约测试，再修改契约与实现。

## 后果

### 正面

- 模块可以使用模拟消息独立实现与测试。
- 所有跨模块数据流可追踪、可审计并能建立隐私守卫。
- 外部能力和单个处理器可以局部失败，不迫使调用方了解内部实现。
- 公共契约为未来拆分提供稳定接口。

### 代价

- 查询也需要异步关联与超时处理，代码量高于直接调用。
- 最终一致性、重复和乱序必须成为正常设计条件。
- 契约变更需要跨负责人评审和兼容测试。

## 验证

- 静态检查阻止业务模块间直接实现导入。
- 集成测试证明查询/响应关联、重复消费幂等和未知主版本拒绝。
- 管理页面的写操作被路由为目标领域 family 的 `Command`，不能直接写业务存储；其他领域不消费 `admin.*` 作为业务命令。
