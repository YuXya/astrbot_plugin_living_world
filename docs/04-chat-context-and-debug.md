# 聊天上下文与调试指南 · 0.2.5

Living World 整理角色、生活、日程、记忆和群消息；AstrBot 继续负责模型、工具、会话和回复。新版调试固定四项，最重要的检查文件是第二项的 API 原始请求。

## 一条消息如何检查

1. 在 **02 角色、模型与模块** 绑定人格，开启被动回复和调试。在「聊天对象与白名单」配置真实 QQ 连接、类型及号码，使该场合使用同一人格。
2. 从配置好的账号发送“莉莉现在日程是什么？”。群聊使用宿主正常唤醒方式，例如 @机器人。
3. 打开「调试与调用记录」，展开最新聊天，先核对对象、时间和第一项中的收到消息。
4. 查看四项内容：

| 项目 | 看什么 |
|---|---|
| ① 上下文与信息来源 | 本次读取、实际选用的资料，来自哪里，加入哪个位置，以及插件实际加入的完整文本。接入诊断只显示在管理页面，不混入模型生活资料。 |
| ② API 原始请求 | SDK 完成格式转换后实际发出的 HTTP JSON 正文。检查 messages / input、system / instructions、模型、工具定义及附加参数。复制和下载直接保留正文，不套 reply.request。 |
| ③ API 原始返回 | 接口返回、尚未经过 SDK 解析的 HTTP 正文。未知字段也保留；接口错误可能返回普通文本。流式是 SSE 事件流，下载 .sse 原文。 |
| ④ 回复阅读版 | 从原文提取正文、接口返回的推理内容、工具、用量及结构化日程；同时展示可取得的正式采用结果、工具公开返回、真实发送内容与状态。流式合并只是阅读结果。 |

同一轮有工具后再次请求或失败重试时，切换“查看第几次请求”，第二、三项始终配对。实际发送和模型生成分别显示，发送成功不代表对方已读或回复。关闭调试、捕获未适配、请求未发出、没有响应或读取失败都会明确说明；缺少原文时不补造。

四项继续通过按钮切换。①中的来源卡片按单列排列，默认全部展开；点击每项标题可单独收起或展开，收起后仍显示出处与注入位置。本次页面内切换视图或请求时保留折叠状态，完整注入文本位于来源列表下方。

②③默认“格式化显示”：JSON 按两空格缩进，正文里的换行转义显示为实际换行，长文本自动折行；可切换“原文”核对保存的正文。格式化仅供阅读，展开字符串换行后的显示文本不保证是有效 JSON；**复制和下载始终保留原文**。字段顺序、重复字段、数字写法与字面量反斜杠保留。SSE 按完整事件格式化其中的 JSON，不合并不同事件；普通错误文本、无法解析的 JSON 与未结束事件按原文展示。

格式化 JSON 中的非空对象和数组默认全部展开，点击左侧小箭头可分别收成 `{…}` 或 `[…]`；也可使用“全部展开”“全部收起”。空容器、提示词字符串中的括号不会出现折叠箭头。收起父层保留子层状态；本次页面内按记录、请求和收发方向分别记住状态，切换视图或原文模式后可继续阅读，正文变化时重新全部展开。SSE 每个完整事件中的 JSON 可独立折叠，元数据和事件边界继续显示。无论收起多少层，复制和下载都保留完整原文。

## 正文里应该有什么

`<living_world_context>` 内现在是分段中文：当前交谈对象、时间、心情作息、地点睡眠、当前活动、今日日程、相关记忆、经历及见闻。UUID、历史条数、数据库记录字段留给程序使用，不再整行塞给模型。没有日程、日程模块关闭、未知状态都用明确的中文说明；计划、角色虚构经历与实际网络证据继续区分。

自动附带的见闻、经历和记忆不再输出链接及“阅读依据／来源／出处”字段。Markdown 链接保留有意义的标题，搜索、旧视频记忆、仅标题等事实边界保留简短说明。普通聊天、主动聊天、日程生成、调整和细化共用清理逻辑；用户消息与宿主历史不改写，来源总结、日记等处理原始证据的任务仍可读取完整来源。管理页面的来源记录及历史调试原文继续保留。

角色日常经历按角色时区只注入今天的记录，显示为 `角色经历（18：00）：自由活动与准备休息。`，在统一说明中标明属于角色虚构日常。时间取实际发生时间，旧记录回退到关联原事件或自身创建时间；无法确认日期的旧角色经历暂不自动注入，不填造时间。知识、人物认知及有效约定保持原有召回规则。

同一事件同时出现在记忆和近期经历时只显示一次，优先保留经历区；不同时间的相似经历不合并。旧记录中的连续重复前缀、重复标题及空条目仅在读取副本中清理，不批量修改历史。新事件与派生记忆在同一事务保存正文、关联标识和发生时间，重复记录不会重置原时间。正式与自动生成的试跑资料采用相同规则，①中的内容是本次实际注入版本，②③仍保存真实收发原文。

寂寞值和精力由程序管理，不向模型投影数值、参数名称、阶段范围或增长消耗规则。仅活动细化的“当前想法”加入请求开始时命中的两段自然语言文案；普通聊天、日程生成和其他后台任务不会自动加入这些文案。细化返回不再允许 `energy_delta`。检查①来源与②原始请求时应看到同次实际使用的文案；管理页面的实时值可能已经变化，不据此改写旧调试记录。试跑读取文案但不扣值，关闭内在状态模块则不注入。

人格和稳定角色资料位于稳定部分，动态资料每轮只加入一次，不写入聊天存档。群聊保留成员与引用关系；私聊沿用当前选中的宿主对话，切换对话后不拼入旧全文。群观察保持 24 条、12,000 字符，替换本轮重复群历史后恢复必要原始历史；不同群和私聊不串资料。

来源清单在组装上下文时同时生成，不会为了显示页面重新检索另一批记忆。最终哪些内容到达 API，请以第二项为准：宿主和其他插件仍可能在请求发送前做处理。

## 捕获范围与旧文件

支持 DeepSeek / OpenAI 兼容 Chat Completions，以及宿主 OpenAI Responses。记录来自原有 SDK HTTP 客户端，不另发请求，不更改端点、模型参数或流式设置。记录的是解压后的 HTTP 正文，不是 TLS 抓包、请求头或网络数据包；已知认证凭据在保存前隐藏。

其他提供商未适配时明确标注。第三方插件内部模型请求不捕获；本插件得到的工具公开结果在阅读版展示。SDK 实际进行的 HTTP 重试分别保存，不能把一次失败重试当成多次 QQ 发送。

旧 `reply.request` 是宿主请求快照，旧 `reply.model.request.arguments` 是 Provider 方法参数，都不是 API 最终 JSON。0.2.3 之前的文件继续可读，并标记“旧版快照，非 API 原文”，无法事后恢复没有记录的原文。旧 response/reply 的兼容读取不表示新日志重复保存两份回复。

正式日程页面的“生成输入快照”用于长期回顾任务输入，“模型生成的日程文本”是从接口回复中提取的文本，都与 HTTP 原文不同。新日程通过关联编号可以跳转到尚未清理的调试记录。

## 白名单与接入状态

未聊过的对象也可接入。只读“检查会话与历史”分别显示找到历史、首次对话、读取失败，以及配置是否允许接入；不调用模型、不发消息、不创建空会话。“最近实际注入”显示真正发生的上下文处理，可跳到该轮记录。配置允许不等于已经注入。

继续按真实会话传入 4.27.5 所需的 provider_settings，遵循会话规则、当前对话人格和宿主默认人格优先级。关闭或清理调试不会抹去最近注入状态，也不会删除宿主聊天历史。

## 保留与试跑

聊天默认保留最近 10 轮，后台每类保留 10 次完整调用，所有重试和子调用一起保留或清理。清理仅影响调试，不删除群观察、正式日程、记忆和发送防重记录。记录属于管理员视图。

可从记录或当前配置建立试跑。试跑编辑的是任务输入，执行后再到第二项检查最终 API 正文；编辑器不是自动回放 HTTP 文件。组合模式编辑模板和动态资料，直接模式编辑 prompt。试跑真实调用模型，但不执行工具、不发 QQ、不改正式生活数据；公共模板只保存明确编辑的模板文本。

验证范围见[实际验收记录](03-delivery-and-validation.md)，自动化、本地 HTTP 对照与真实 QQ / 在线模型联调分开记录。
