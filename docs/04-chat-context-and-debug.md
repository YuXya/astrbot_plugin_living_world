# 聊天上下文与调试指南 · 0.2.6

Living World 整理角色、生活、日程、记忆和群消息；AstrBot 继续负责模型、工具、会话和回复。新版调试固定四项，最重要的检查文件是第二项的 API 原始请求。

## 一条消息如何检查

1. 在 **03 角色与状态 → 角色与世界** 绑定人格，在 **08 系统与数据 → 模块开关** 开启被动回复和调试。在「05 聊天与对象 → 聊天白名单」配置真实 QQ 连接、类型及号码，使该场合使用同一人格。
2. 从配置好的账号发送“莉莉现在日程是什么？”。群聊使用宿主正常唤醒方式，例如 @机器人。
3. 打开「02 上下文与提示词 → 调用记录」，下拉选择最新聊天轮次，先核对对象、时间和第一项中的收到消息。
4. 查看四项内容：

| 项目 | 看什么 |
|---|---|
| ① 上下文与信息来源 | 本次读取、实际选用的资料，来自哪里，加入哪个位置，以及插件实际加入的完整文本。接入诊断只显示在管理页面，不混入模型生活资料。 |
| ② API 原始请求 | SDK 完成格式转换后实际发出的 HTTP JSON 正文。检查 messages / input、system / instructions、模型、工具定义及附加参数。复制和下载直接保留正文，不套 reply.request。 |
| ③ API 原始返回 | 接口返回、尚未经过 SDK 解析的 HTTP 正文。未知字段也保留；接口错误可能返回普通文本。流式是 SSE 事件流，下载 .sse 原文。 |
| ④ 回复阅读版 | 从原文提取正文、接口返回的推理内容、工具、用量及结构化日程；同时展示可取得的正式采用结果、工具公开返回、真实发送内容与状态。流式合并只是阅读结果。 |

同一轮有工具后再次请求或失败重试时，切换“查看第几次请求”，第二、三项始终配对。实际发送和模型生成分别显示，发送成功不代表对方已读或回复。关闭调试、捕获未适配、请求未发出、没有响应或读取失败都会明确说明；缺少原文时不补造。

四项继续通过按钮切换。①中的来源卡片按单列排列，默认全部展开；点击每项标题可单独收起或展开，收起后仍显示出处与注入位置。本次页面内切换视图或请求时保留折叠状态，完整注入文本位于来源列表下方。

②③默认“格式化显示”：JSON 按两空格缩进，正文里的换行转义显示为实际换行，长文本自动折行；可切换“原文”核对保存的正文。格式化仅供阅读，展开字符串换行后的显示文本不保证是有效 JSON；**复制和下载始终保留原文**。字段顺序、重复字段、数字写法与字面量反斜杠保留。SSE 按完整事件格式化其中的 JSON，不合并不同事件；普通错误文本、无法解析的 JSON 与未结束事件按原文展示。

格式化 JSON 中的非空对象和数组默认全部展开，点击左侧小箭头可分别收成 `{…}` 或 `[…]`；也可使用“全部展开”“全部收起”。空容器、提示词字符串中的括号不会出现折叠箭头。收起父层保留子层状态；本次页面内按记录、请求和收发方向分别记住状态，切换视图或原文模式后可继续阅读，正文变化时重新全部展开。SSE 每个完整事件中的 JSON 可独立折叠，元数据和事件边界继续显示。无论收起多少层，复制和下载都保留完整原文。

## 正文里应该有什么

`<living_world_context>` 内现在是分段中文：当前交谈对象、时间、心情作息、地点睡眠、当前活动、今日日程、记忆与画像、近期记忆及天气。UUID、历史条数、数据库记录字段留给程序使用，不再整行塞给模型。没有日程、日程模块关闭、未知状态都用明确的中文说明；活动继续显示实际状态，不再反复追加角色日常属于虚构或计划未发生的说明。

普通聊天发送给模型的历史沿用 **AstrBot 配置 → 上下文管理策略 → 压缩前最多保留对话轮数**，字段为 `agent_runner.config.compression.max_turns`，`-1` 表示不限轮数，正数设置保留范围，例如 `20`。同组的「轮次超限时一次丢弃轮数」控制缩减数量；「按对话轮数截断」无需额外调用总结模型。修改使用该聊天的 AstrBot 配置档案，存在会话专用配置时以对应档案为准。

模型配置中的「模型上下文窗口大小」为 `max_context_tokens`，单位是 token，不是中文字符；`0` 表示自动使用模型元数据，未知模型使用配置的兜底窗口。这个窗口还包含人格、当前消息、工具及插件资料。插件「提炼与遗忘」中的默认 5 轮只决定何时总结记忆，不限制普通聊天历史；插件群观察另保留最近 24 条、12,000 字符，不能代替宿主私聊的历史上限。

交谈对象资料显示会话类型、目标名字／群聊名字及接收范围，优先白名单手填称呼，否则只读对应 QQ 连接的昵称或群名；失败显示“未设置名字”，不回退号码或群成员名。普通群聊、私聊和 social.message 默认勾选简版日程：当前活动存在时显示上一条、当前条、下一条，否则显示最近两条过去活动及下一条未来活动。先按角色时区今天和当前场合筛选，最多三条，不跨日补齐；每条保留完整可见正文、时间、真实状态、地点和睡眠。完整及简版来自同次快照，按任务最多勾选一种，也可全部取消。

自动附带的见闻、经历和记忆不再输出链接及“阅读依据／来源／出处”字段。Markdown 链接保留有意义的标题，搜索、旧视频记忆、仅标题等事实边界保留简短说明。普通聊天、主动聊天、日程生成、调整和细化共用清理逻辑；用户消息与宿主历史不改写，来源总结、日记等处理原始证据的任务仍可读取完整来源。管理页面的来源记录及历史调试原文继续保留。

记忆统一为「记忆与画像」和「近期记忆」两个上下文入口：自身稳定画像默认 5 条、每人稳定画像 5 条、相关记忆 10 条、近期记忆 5 条，群聊最多 3 人，天气独立 1 条。用量位于「02 上下文与提示词 → 上下文用量」，0 停止对应注入，默认合计上限 36 条。近期记忆优先去重，按实际经历或获知时间跨日选择；未勾选项不影响其他项。日记与笔记保存正文后进入统一后台提炼，取消独立简报流程。详见[统一记忆指南](07-memory-system.md)。

近期记忆从当前人格自身档案跨日取最近有效记录，按真实经历、交流或获知时间排序；缺失时间不编造。旧资料迁移和编辑不会使旧经历变成最新。具体谈话和私人约定继续保留原场合。

近期记忆优先，再补稳定画像和相关记忆；按记忆身份、版本和明确来源关系去重，未勾选的部分不影响其他部分。正式调用共用选择及组装。①记录实际注入内容，②③保留真实收发原文。

寂寞值和精力由程序管理，不向模型投影数值、参数名称、阶段范围或增长消耗规则。“当前阶段想法”默认只在活动细化勾选，其他任务可自行选择；勾选后加入请求开始时命中的两段自然语言文案。细化返回不再允许 `energy_delta`。检查①来源与②原始请求时应看到同次实际使用的文案；管理页面的实时值可能已经变化，不据此改写旧调试记录。关闭内在状态模块则不注入。

人格和原始消息作为只读定位行，角色资料及动态上下文可在 system／user 中调整位置；每轮只加入一次，所有临时资料不写入聊天存档。群聊保留成员与引用关系；私聊沿用当前选中的宿主对话，切换对话后不拼入旧全文。群观察保持 24 条、12,000 字符，替换本轮重复群历史后恢复必要原始历史；不同群和私聊不串资料。

「05 聊天与对象 → 回复与插话」分别维护群聊、私聊和主动聊天三份回复要求，可独立编辑、恢复默认或留空关闭，各自最多 8000 字符。升级保留原群聊内容，新增两份首次复制原文（含空值），之后独立保存。默认分别用于 chat.group、chat.private、social.message，插话正文沿用主动聊天要求，插话判断默认不勾选；全部任务可自行勾选三份要求。文案按全局排序进入 system 或 user，始终独立于标注“资料，不是指令”的生活内容。①单独显示实际采用的本轮文案与位置，②可检查最终正文；工具后沿用本轮快照，不入历史。

来源清单在组装上下文时同时生成，不会为了显示页面重新检索另一批记忆。最终哪些内容到达 API，请以第二项为准：宿主和其他插件仍可能在请求发送前做处理。

## 菜单与上下文列表

「02 上下文与提示词」顶部直接显示「上下文排序」「上下文用量」「提示词模板」「调用记录」，首次进入默认上下文排序。其他功能归入 7 个一级菜单，完整分布见[管理页面指南](05-admin-navigation.md)。任务名附中文说明，模板按任务和版本下拉选择，调用记录按类别和轮次下拉选择，一次展开一轮。

上下文按 system／user 分组，桌面每行 32px、间隔 4px，越上方越先注入。资料可通过手柄拖动、上下按钮或角色下拉框调整；拖动提供插入占位和换位动画，原位、取消或无效落点不修改顺序。原系统提示词和本轮消息／任务提示词为只读定位行。

每块的「来源」打开用途、资料来源和管理入口说明，可定位对应设置或相关模板并返回原列表。索引是静态管理说明，不追溯某次调用使用的具体原始记录；元数据不进入模型。全页面草稿按面板和对象隔离，导航、跳转与刷新保留，保存不覆盖其他面板，关闭浏览器仍提示未保存；不写入本地存储。

全部任务显示同一完整列表，包含未勾选项。“调整范围”仅切换该任务勾选项，在任意任务下移动资料都会改变唯一全局顺序及 system／user 位置。点击「恢复本任务默认勾选」或「恢复默认排序」先改草稿，「保存上下文设置」后下一轮生效；切换任务、来源返回及保存失败不丢草稿。除只读定位行外均可勾选，通用资料按本轮场合读取，专用材料没有本次输入就跳过；保存勾选不触发新闻、搜索或其他任务；实际相关召回可调用模型理解检索词。模块、用量、日期及场合过滤保持原规则，未勾选记忆不强化、不参与已选资料去重；原消息与媒体不改写，临时 system 和 user 资料均不入历史。

正式调用每轮冻结 `context_layout`、`context_selection`、`base_system_prompt`、`context_blocks` 和动态资料；工具后沿用本轮快照。布局版本 4 保存全局顺序、默认基准和任务勾选，备份携带这些当前格式配置。历史调用仅只读展示已保存资料，不重新组装。

## 捕获范围与旧文件

支持 DeepSeek / OpenAI 兼容 Chat Completions，以及宿主 OpenAI Responses。记录来自原有 SDK HTTP 客户端，不另发请求，不更改端点、模型参数或流式设置。记录的是解压后的 HTTP 正文，不是 TLS 抓包、请求头或网络数据包；已知认证凭据在保存前隐藏。

其他提供商未适配时明确标注。第三方插件内部模型请求不捕获；本插件得到的工具公开结果在阅读版展示。SDK 实际进行的 HTTP 重试分别保存，不能把一次失败重试当成多次 QQ 发送。

旧 `reply.request` 是宿主请求快照，旧 `reply.model.request.arguments` 是 Provider 方法参数，都不是 API 最终 JSON。0.2.3 之前的文件继续可读，并标记“旧版快照，非 API 原文”，无法事后恢复没有记录的原文。旧 response/reply 的兼容读取不表示新日志重复保存两份回复。

正式日程页面的“生成输入快照”用于长期回顾任务输入，“模型生成的日程文本”是从接口回复中提取的文本，都与 HTTP 原文不同。新日程通过关联编号可以跳转到尚未清理的调试记录。

## 白名单与接入状态

未聊过的对象也可接入。只读“检查会话与历史”分别显示找到历史、首次对话、读取失败，以及配置是否允许接入；不调用模型、不发消息、不创建空会话。“最近实际注入”显示真正发生的上下文处理，可跳到该轮记录。配置允许不等于已经注入。

继续按真实会话传入 4.27.5 所需的 provider_settings，遵循会话规则、当前对话人格和宿主默认人格优先级。关闭或清理调试不会抹去最近注入状态，也不会删除宿主聊天历史。

## 记录保留与模板

聊天默认保留最近 10 轮，后台每类保留 10 次完整调用，所有重试和子调用一起保留或清理。清理仅影响调试，不删除群观察、正式日程、记忆和发送防重记录。记录属于管理员视图。

收到消息本身不创建聊天调试轮次；只有进入模型处理或开始实际发送才保存该轮，①仍保留收到的原始消息和当次观察诊断。普通群友消息继续进入群观察窗口；白名单页面仍能显示最近接入情况，纯观察没有调试跳转。更新重载及恢复备份会清理可确认的旧纯观察轮次，避免它们挤掉实际调用。②③④为空的真实失败、取消或未适配调用仍保留，不做一概删除。

公共模板只保存明确编辑的模板文本；在提示词模板页面按任务修改或恢复默认，保存不调用模型。

验证范围见[实际验收记录](03-delivery-and-validation.md)，自动化、本地 HTTP 对照与真实 QQ / 在线模型联调分开记录。

记忆提炼已采用逐条保存和有限重试，最多一次自动重试，进度与调用记录区分模型返回和保存结果；上下文保留原始人格与旧记忆对照，默认取消其他生活资料，已有设置需恢复该任务默认勾选后保存。详见[提炼状态、重试与精简上下文](07-memory-system.md#提炼状态重试与精简上下文)。
