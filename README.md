# 我也在这个世界生活 / Living World

**0.2.4 可安装测试版本，支持 AstrBot `>=4.27.5,<5`、Python 3.12、OneBot QQ 群聊与私聊。** 日程先生成活动大纲，临近活动再决定新闻、搜索和主动聊天；三个数量改为立即生效的每日执行上限。保留四项调试、API 实际 HTTP 原文与中文生活上下文。真实在线模型、QQ、和风天气及 B 站联调仍待完成。

角色沿用你选择的 AstrBot 人格，积累生活经历、知识和人物关系。每天先安排上课、散步、阅读等活动，细化时再结合具体需要安排新闻、搜索或主动聊天。角色虚构经历、计划和已经执行的真实行动分别记录；私人约定保留所属聊天场合。

## 日程与聊天

- 默认每天 **06:00** 生成一次正式活动大纲，共 **10 个活动**，只含时间、内容、地点和睡眠状态。生成时间和活动数修改默认次日生效。
- 默认提前 **10 分钟**细化活动。AI 结合活动、人格、状态、相关记忆、当天其余安排、近期实际行动及剩余额度，决定是否安排三项行动，给出理由、意图和时间。允许全部不安排；每个活动每类最多一次，多类可共存，按 **新闻 → 搜索 → 聊天** 执行。
- 每日执行上限默认 **新闻 2 次、搜索 2 次、主动聊天 3 轮**，分别可设为 0—48，允许少做、不凑数。保存后立即约束尚未执行的行动；降低上限保留时间较早且容得下的预留，提高上限供后续细化使用，不自动重细化旧活动。
- 细化采用后预留名额；执行前跳过会释放，真正开始执行后计入角色时区对应日期的用量，失败或结果未确认也不退还。**一轮主动聊天可以抽选多个不同对象**，各对象仍受白名单、每日发送上限、冷却、免打扰及防重复限制。
- 未开始活动可点击 **「细化活动／重新细化」**，填写“本次要求”，例如“这次专心散步，不安排主动聊天”；要求不写入公共模板。合格后替换旧细化，失败保留旧结果。自动细化失败后，在活动开始前至少间隔 60 秒再试一次；仍失败则保留活动大纲，不新增行动。
- **「编辑／批量调整未来活动」**只修改未开始活动大纲，保留活动总数；修改后旧细化归档作废、预留释放，之后重新细化。私人场合调整保持场合隔离，过期行动不补发。
- **「重新生成日程」**用最新已保存参数重做今天整份大纲。合格后立即采用，旧版本和执行结果归档；失败保留旧日程。未来活动细化后照常执行，但当天已使用次数、发送次数和冷却不清零。
- 主动消息在执行时结合目标场合的聊天历史与记忆生成，计划不会冒充已发送或已得到回复。独立随机阅读、搜索和临时主动联系已取消；正常回复、群聊插话分别控制。管理员手动读取来源是明确的真实调用，与活动行动用量分开记录。

## 白名单在哪里

打开插件的 **Plugin Pages → 左侧「聊天对象与白名单」**。首页「今日生活」顶部和「日程与行动」页也有直达按钮。

点击「添加聊天对象」，填写 **QQ 连接、群聊／私聊、号码、启用、权重**，再保存。完整会话 ID 自动生成，旧 UMO 配置继续兼容。人格和记忆使用实际会话场合判断；同一群开启独立用户会话后，也不会将某人的私人上下文混入其他场合。

**未聊过也可以接入。**「检查会话与历史」显示当前真实会话、人格和找到历史／首次对话／读取失败；只读取状态，不调用模型、不发送消息、不创建空会话。

0.2.2 中，“配置允许接入”仅表示连接和人格等配置有效；发送一条消息后再检查“最近实际注入”，可直达对应调试轮次。人格来源会区分宿主默认设置、当前对话指定和会话规则。聊天会携带当前时间、当前活动和当天日程摘要，无日程或模块关闭时明确说明。

Living World 组织角色资料、生活状态、日程和相关记忆，模型、工具及回复继续走 AstrBot。私聊使用当前选中的对话，动态资料放在本轮请求末尾，不重复存入历史；首次主动联系成功后存入宿主会话。群聊独立观察最近 24 条、12,000 字符，生成时替换重复宿主群历史，保存前恢复原始历史。观察不依赖插话开关或宿主群历史开关。

## 固定来源与见闻

| 能力 | 配置及行为 |
|---|---|
| 新闻 | 内置 BBC 中文、Google 新闻中文、Solidot、Hacker News、MIT Technology Review、Ars Technica；可逐项修改、启停和恢复默认。取得候选后由 AI 选择、读取并写感想。 |
| 搜索 | 自动使用 AstrBot 已配置的网页搜索服务；AI 结合活动和记忆选题，实际搜索后写见闻。普通页面无需填写工具名或参数名。 |
| 天气 | 固定和风天气，只需地点、API Host、API Key 或 JWT 凭据。连接测试不写生活数据；自动刷新成功间隔 90 分钟，失败退避 15 分钟，不调用 AI。 |
| B 站 | 固定依赖 `astrbot_plugin_bilibili_ai_bot` 的搜索、指定视频观看及公开记忆 API v3。缺失依赖只影响 B 站和依赖它的 AI 日报。 |
| AI 日报 | 黑鸦 Heya 默认 **12:00**、橘鸦 Juya 默认 **23:00**，时间可改，每路每天一次。不占活动行动的每日上限，不额外触发聊天，重启不集中补读。 |

见闻分别保留标题、选择理由、事实摘要、角色感想、来源和阅读依据。无法读取正文时明确标为标题或订阅摘要；模型整理失败只保留实际证据，并标记为部分完成。B 站搜索不等于观看，旧视频记忆不等于新观看；日报确认作者和当日发布日期后才观看，无法核对则跳过。

## 安装、调试与升级

1. 在 AstrBot 插件管理中导入 `astrbot_plugin_living_world-0.2.4.zip`，安装其 `requirements.txt` 依赖后加载。可选依赖 Bilibili AI Bot 需另行安装配置；生活和记忆不依赖两个参考插件。
2. 打开 Plugin Pages，在「角色、模型与模块」绑定人格、补充角色与世界资料。模型可留空沿用宿主，或设置默认模型及业务覆盖。
3. 填写测试白名单，使目标会话在 AstrBot 中使用同一人格。宿主群历史可用于初始化；未开启时从新消息开始观察。使用本插件插话时关闭宿主概率回复，否则本插件暂停插话。
4. 在「日程与行动」分别设置大纲参数和行动每日上限，在「内容来源」配置外部能力，按需要开启模块。初次未绑定人格时不会自动行动；主动社交、插话及外部能力默认关闭。
5. 在「调试与调用记录」展开一轮，查看 **①上下文与信息来源、②API 原始请求、③API 原始返回、④回复阅读版**。工具后请求及失败重试可切换查看。聊天默认保留最近 **10 轮完整记录**，后台每类 **10 次完整调用**。试跑只调用模型，不执行工具、不发 QQ、不改正式生活数据。

检查 AI 实际收到的内容，请用 **②API 原始请求**。它来自 AstrBot SDK 最终发送的 HTTP 请求体，保留消息、工具和附加参数，仅隐藏已知认证凭据；下载不套包装。③保存接口解析前的返回正文，流式为原始 SSE 文件；④单独整理文字、推理、工具、用量及采用结果。支持 DeepSeek/OpenAI 兼容 Chat Completions 和 OpenAI Responses；未适配、未调用或捕获失败明确显示，不用 Provider 参数代替。旧日志标为“旧版快照，非 API 原文”。正式日程另存生成输入快照、模型生成文本和校验后日程。详见[聊天上下文与调试指南](docs/04-chat-context-and-debug.md)。

**本次升级会自动转换旧日程。** 先归档旧版本，未开始活动保留大纲和场合，移除旧行动标记及旧细化，等待新规则细化；已经开始的活动保留决定与执行记录。已发起行动去重计入当天用量，旧独立行动退出旧队列，不重放。生成、细化和调整日程的旧自定义模板备份后启用新默认模板，可在调试页查看旧指令；之后的新修改不被再次升级覆盖。

升级保留记忆、白名单、实际发送、冷却与防重记录，不改变 SQLite 表结构。配置与数据位于 AstrBot 插件数据目录的 `astrbot_plugin_living_world/living_world.sqlite3`；Plugin Pages 是唯一配置入口，没有 `_conf_schema.json`。备份包含管理员可见的私人资料及配置凭据，应在可信位置保存；恢复会合并缺失记录、保留已有 ID，并关闭全部业务模块，旧数据转换后再参与运行，已退役活动不会重新获得执行资格。

完整步骤见[安装与测试说明](docs/02-install-and-test.md)，验证范围见[交付与验收记录](docs/03-delivery-and-validation.md)。开发安排见[总计划](docs/01-lead-plan.md)、[任务索引](docs/README.md)及[协作规则](AGENTS.md)。
